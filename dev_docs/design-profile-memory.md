# Память профилей ИИ (Profile Memory) — архитектура и реализация

Статус: проектирование.  
Дата: 2026-10-26.  
Стек: Vue 3, Pinia, TypeScript, Rust (Tauri 2), `@bozonx/ai-kit`.  
Связанные документы: [plan-chat-tools.md](plan-chat-tools.md), [config-storage.md](config-storage.md), [architecture.md](architecture.md).

## 1. Цели и границы

Профили ИИ в TyCo (`ai-vault/profiles/<profile-id>/`) представляют собой тематических ассистентов, консультантов и виртуальных специалистов (например, личный помощник, доктор, архитектор проекта, копирайтер). Профили работают в связке с изолированной файловой рабочей областью (`workspace/`) и подключенными проектами.

Данный документ определяет архитектуру **долговременной памяти профилей** без использования внешних библиотек и тяжелых векторных баз данных.

### Что делаем:

- **Файловая структурированная память в Markdown:** Хранение долговременных знаний, контекста пользователя и истории решений непосредственно в каталоге `workspace/memory/` профиля.
- **Двухуровневая модель памяти:**
  1. _Ядро (Core State):_ Постоянные факты, ограничения, привычки и глобальные предпочтения пользователя (`core.md`).
  2. _Тематические карточки (Topic Notes):_ Знания, сгруппированные по предметным областям (`topics/*.md`).
  3. _Хронологический архив (Journal / Timeline):_ Датированные логи ключевых событий и встреч (`journal/YYYY-MM.md`).
- **Работа через существующие файловые инструменты:** Использование уже реализованных в фазе 2 инструментов (`read_file`, `write_file`, `edit_file`, `search_files`, `list_files`).
- **Human-in-the-loop (прозрачность и контроль):** Пользователь может в любой момент открыть файлы памяти в редакторе, дополнить, поправить ошибки модели или удалить приватную информацию.
- **Офлайн и zero-dependency:** Никаких сетевых запросов, облачных сервисов памяти или бинарных баз данных. Память перемещается и бэкапится вместе со всем `ai-vault`.

### Что НЕ делаем:

- **Векторные базы данных и эмбеддинги на первом этапе:** Векторные индексы (Chroma, SQLite-vec) требуют локальных тяжелых моделей эмбеддингов или вызовов внешних API, что усложняет сборку под Linux, Windows и macOS и противоречит легковесности TyCo. Для десктопного ассистента поиск через `search_files` (быстрый ripgrep в Rust) покрывает подавляющее большинство сценариев.
- **Фоновые автономные демоны:** TyCo не выполняет неконтролируемых фоновых задач без пользователя. Чтение, обновление и уплотнение памяти выполняются строго в рамках хода диалога (`turn`), инициированного пользователем.
- **Непрозрачный дамп истории:** Память не дублирует историю чатов (`chats/`). Она хранит только дистиллированные факты, выводы и текущее состояние дел.

## 2. Структура каталогов и форматы файлов

Память каждого профиля физически располагается в подпапке `memory/` его рабочей области `workspace/`:

```text
~/.local/share/com.tyco.app/ai-vault/profiles/<profile-id>/
├── profile.json               # Настройки профиля и инструментов
├── SOUL.md                    # Корневой системный промпт профиля
├── chats/                     # История диалогов
└── workspace/                 # Рабочая область (всегда политика allow)
    ├── uploads/               # Загруженные пользователем вложения
    └── memory/                # Каталог долговременной памяти профиля
        ├── core.md            # Ядро: профиль пользователя и ключевые факты
        ├── topics/            # Тематические модули
        │   ├── health.md      # Пример для профиля-доктора
        │   ├── stack.md       # Пример для технического ассистента
        │   └── preferences.md # Стиль ответов, язык, правила
        └── journal/           # Датированные логи по месяцам (опционально)
            ├── 2026-09.md
            └── 2026-10.md
```

### 2.1. `core.md` (Ядро памяти)

Файл содержит фундаментальные сведения, которые актуальны всегда или очень долго. Рекомендуемый размер — до 2–4 КБ.

Пример содержимого:

```markdown
# Ядро памяти профиля

## О пользователе

- Имя: Иван
- Часовой пояс: UTC-3
- Язык общения: Русский

## Ключевые постоянные факты

- Проект: TyCo (десктопное приложение Tauri 2 + Vue 3 + Rust).
- Предпочитаемый пакетный менеджер: pnpm.
- Ограничения: аллергия на пенициллин (для медицинского профиля).

## Важные глобальные правила

- Не предлагать облачные решения, если задача решаема локально.
```

### 2.2. `topics/*.md` (Тематические модули)

Файлы создаются моделью или пользователем под конкретные сферы ответственности профиля.

- Модель «Семейный доктор»: `health_history.md`, `medications.md`, `allergies.md`.
- Модель «Помощник по коду»: `architecture_decisions.md`, `project_conventions.md`.
- Модель «Личный ассистент»: `people.md`, `routines.md`, `wishlist.md`.

Структура внутри тематического файла — списки и markdown-таблицы с краткими тезисами.

### 2.3. `journal/YYYY-MM.md` (Хроника / архив)

Журналы ведутся с разбивкой по месяцам для записи датированных событий:

- «2026-10-15: Сданы анализы крови, гемоглобин в норме».
- «2026-10-20: Принято решение перейти на Tauri 2».

**Принцип устаревания:** Записи старше 1–2 месяцев считаются архивными. Если в них зафиксирован факт, сохраняющий актуальность, модель переносит (консолидирует) его в `core.md` или `topics/`, а запись в журнале оставляет как исторический лог. При стандартных запросах модель не читает старые файлы журнала, обращаясь к ним только по прямому указанию пользователя.

## 3. Механизм взаимодействия модели с памятью

Взаимодействие строится на сочетании контекстной инъекции ядра и инструментального чтения/записи по требованию.

### 3.1. Чтение памяти (Retrieval)

1. **Автоматическая инъекция `core.md`:**
   При формировании запроса к LLM (`apps/desktop-ui/src/lib/chat/chat-request-preparation.ts`) система проверяет наличие `workspace/memory/core.md`.
   - Если файл существует и его размер не превышает лимит (например, 3 000 символов), он автоматически подмешивается в системный контекст в блоке `<profile_memory>`.
   - Это гарантирует, что модель с первого же сообщения «помнит» ключевые вещи без траты шагов инструментов (`tool calls`) на чтение файла.

2. **Чтение по требованию (On-Demand via Tools):**
   - Если вопрос касается деталей проекта, предыстории или специфической темы, модель использует `read_file("workspace/memory/topics/...")` или `search_files("ключевое слово", "workspace/memory")`.
   - Модель знает о структуре своих папок благодаря системной подсказке.

### 3.2. Запись и обновление памяти (Writing & Updating)

Модель сохраняет знания во время своего хода через инструменты:

1. **Дистилляция, а не стенограмма:** Модель не копирует реплики диалога, а формулирует факт:
   - Было: _«Знаешь, у меня вчера сильно болела голова после кофе, больше его не пью»_.
   - Запись в `health.md`: `- Непереносимость кофеина: вызывает головные боли (зафиксировано в октябре 2026)`.
2. **Атомарные правки (`edit_file`):** Модель обновляет существующие списки, а не просто дописывает файл в конец, предотвращая раздувание и противоречия.
3. **Безопасность:** Поскольку `workspace/` профиля всегда имеет политику `allow`, вызовы `write_file` и `edit_file` в папку `workspace/memory/` выполняются бесшовно, не прерывая диалог запросами подтверждения (в отличие от изменения файлов в пользовательских проектах).

### 3.3. Уплотнение и очистка (Memory Consolidation)

Чтобы память не переполняла контекст и дисковое пространство:

- **Пороговое сжатие:** Когда размер тематического файла превышает лимит (например, 8–10 КБ), системный промпт инструктирует модель выполнить оптимизацию: удалить дубли, объединить связанные пункты, убрать устаревшие и потерявшие актуальность задачи.
- **Архивация:** Завершенные процессы и старые вехи переносятся в `journal/`, освобождая активный `core.md`.

## 4. Системные инструкции (Промпты)

В `SOUL.md` профиля (или через системную вставку `ChatToolProvider.instructions`) добавляется блок управления памятью:

```markdown
## Долговременная память

У тебя есть доступ к каталогу памяти `workspace/memory/`:

- `core.md`: твои главные постоянные знания о пользователе и правилах.
- `topics/`: тематические заметки по ключевым направлениям твоей роли.
- `journal/`: помесячный архив событий (`YYYY-MM.md`).

Правила работы с памятью:

1. Извлекай важные факты: когда пользователь делится важной долгосрочной информацией,
   предпочтениями или решениями, обновляй соответствующие файлы через `edit_file` или `write_file`.
2. Будь лаконичен: записывай только дистиллированные факты и выводы в виде списков или таблиц,
   не сохраняй промежуточный диалог.
3. Актуализируй: если старые данные изменились, заменяй их через `edit_file`, а не дублируй.
4. Приоритет актуальности: файлы в корне `memory/` и `topics/` отражают текущее состояние;
   старые файлы в `journal/` используй только при явных вопросах об истории или предыстории.
```

## 5. UI и пользовательский опыт (UX)

Для соблюдения принципа подконтрольности пользователю реализуется:

1. **Вкладка «Память» в настройках профиля:**
   - В `apps/desktop-ui/src/components/settings/SettingsProfileDetailTab.vue` рядом с `SOUL.md` отображается раздел «Память профиля».
   - Список файлов из `workspace/memory/` с возможностью быстрого открытия во встроенном редакторе.
2. **Быстрое редактирование:**
   - Пользователь видит, что ассистент «помнит» о нем, может скорректировать формулировку или удалить приватные записи.
3. **Кнопка сброса/очистки:**
   - Действие «Очистить память профиля» с подтверждением — удаляет или очищает каталог `workspace/memory/`, не затрагивая остальные файлы проекта.

## 6. План поэтапной реализации

### Фаза 1: Структура каталогов и инициализация шаблонов

- При создании нового профиля в `services/ai_vault/operations.rs` автоматически создается директория `workspace/memory/` и начальный `core.md`.
- Добавление типовых шаблонов памяти под роли профилей (ассистент, разработчик, доктор/консультант).
- Обновление базового шаблона `SOUL.md` инструкциями по работе с `workspace/memory/`.

### Фаза 2: Авто-инъекция `core.md` в контекст

- В `apps/desktop-ui/src/lib/chat/chat-request-preparation.ts` и `chat-profile-runtime.ts`:
  - Проверка наличия и размера `workspace/memory/core.md`.
  - Включение его содержимого в системный контекст запроса с ограничением по объему символов.
  - Учет размера `core.md` в расчете бюджета контекста (`chat-context.ts`).

### Фаза 3: Пользовательский интерфейс управления памятью

- Отображение файлов памяти в карточке настроек профиля.
- Встроенный просмотр и Markdown-редактор для файлов `workspace/memory/`.
- Кнопка очистки памяти с подтверждением.

### Фаза 4: Тестирование и верификация

- Модульные тесты на создание профиля с памятью и изоляцию путей.
- Тесты на корректность инъекции контекста и соблюдение лимитов бюджета.
- Тестирование на реальных сценариях (Gemini / DeepSeek / локальные модели через openai-compatible): проверка вызовов `write_file`/`edit_file` для сохранения фактов о пользователе и последующего их извлечения в новых диалогах.
