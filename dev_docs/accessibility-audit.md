# Комплексный аудит доступности (Accessibility / a11y) TyCo

**Дата проведения:** Октябрь 2026 г.  
**Статус:** Выполнен  
**Область аудита:** Все окна и оверлеи приложения (`main`, `quick`, `voice`, лаунчер команд, чат, настройки, общие компоненты `common`).  
**Стандарты оценки:** WCAG 2.1 / 2.2 (уровни AA и частично AAA), WAI-ARIA 1.2, специфика Assistive Technology для desktop-окружений (Linux/Orca, Windows/NVDA/JAWS, macOS/VoiceOver).

---

## 1. Введение и архитектурная специфика TyCo

TyCo — это офлайн-ориентированный desktop AI-компаньон для работы с текстом. В отличие от обычных веб-сайтов или классических оконных программ, TyCo совмещает три роли:

1. **Основное рабочее окно (`main`):** редактор текста, чат с ИИ, история и панель настроек.
2. **Всплывающий оверлей быстрого доступа (`quick`):** вызывается поверх других окон ОС по глобальной горячей клавише для быстрого ввода, запуска команд и диктовки.
3. **Полноценная ассистивная утилита (Assistive Technology):** благодаря голосовому вводу (STT) и автоматизации команд через хоткеи приложение объективно востребовано людьми с инвалидностью и ОВЗ.

Для подобных утилит доступность — это не формальное соответствие чек-листу, а **ключевой фактор применимости продукта**.

---

## 2. Методология проведения аудита

Аудит проведён с использованием комплексного подхода:

- **Автоматизированное e2e-тестирование:** запуск Playwright на базе движка Chromium в headless-окружении для оценки DOM, расчёта доступных имён (Accessible Name Computation), дерева доступности и состояний псевдоклассов (`:focus-visible`).
- **Анализ цветовых пространств и контрастности:** вычисление контраста цветов в палитрах Light, Dark и E-ink с учётом современных цветовых моделей `oklab(...)` и `lab(...)`.
- **Анализ разметки компонентов Vue 3:** проверка семантики HTML, использования ARIA-атрибутов (`role`, `aria-live`, `aria-atomic`, `aria-label`, `aria-keyshortcuts`).
- **Анализ клавиатурного взаимодействия:** проверка фокусных ловушек (Focus Traps), порядка табуляции, перехвата системных клавиш (`Tab`, `Space`, `Enter`, `Escape`) и одноклавишных шорткатов.
- **Анализ аудио- и обратной связи:** проверка наличия звуковых сигналов (earcons) при голосовой активации.

## 3. Аудит по целевым категориям пользователей

### 3.1. Пользователи с нарушениями моторики (Keyboard-only, тремор, параличи, RSI, одноручный ввод)

#### Что уже реализовано хорошо:

- Базовый сценарий «хоткей $\to$ диктовка $\to$ автоматическая вставка в стороннее приложение» избавляет от необходимости пользоваться мышью.
- Модальные окна ([`BaseDialog.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/common/BaseDialog.vue)) корректно удерживают клавиатурный фокус внутри окна через нативный `showModal()` и закрываются по `Escape`.
- Меню и выпадающие списки ([`DropdownMenu.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/common/DropdownMenu.vue), [`EditorContextMenu.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/editor/EditorContextMenu.vue)) поддерживают навигацию стрелками (`ArrowUp`, `ArrowDown`, `Home`, `End`).

#### Выявленные проблемы и риски:

1. **Блокировка стандартной табуляции в [`ShortcutList.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/overlay/ShortcutList.vue#L147-L148):**
   - Нажатие клавиши `Tab` жестко перехвачено: `if (event.code === 'Tab' && props.isEditorButtonVisible) { event.preventDefault(); goToEditor(); }`.
   - Пользователь, привыкший перемещаться по элементам интерфейса клавишей `Tab`, лишается этой возможности: фокус не перемещается на кнопки команд, а окно мгновенно переключается на редактор.
2. **Отсутствие видимого фокуса на кнопках команд [`ShortcutButton.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/overlay/ShortcutButton.vue):**
   - Кнопки используют кастомный класс `.shortcut`, у которого нет селектора `:focus-visible`. Замеры показали `outlineStyle: "none"`. При табуляции невозможно понять, какая кнопка активна.
3. **Отсутствие стрелочной навигации по сетке команд 5x3:**
   - 15 слотов команд (`qwert / asdfg / zxcvb`) отрисованы как CSS Grid, но не поддерживают стрелочную навигацию (паттерн WAI-ARIA Grid/Toolbar). Пользователь вынужден нажимать физическую букву на клавиатуре либо перебирать элементы длинным табом.
4. **Опасность одиночных клавиш без модификаторов (WCAG 2.1.4 Character Key Shortcuts):**
   - Буквы `Q..B` в лаунчере запускают действия сразу по нажатию. Для людей, использующих внешние программы голосового ввода (Dragon, Talon) или альтернативные переключатели (switch access), это приводит к случайным запускам команд.
5. **Тайминги завершения записи голоса:**
   - В настройках отсутствует регулировка задержки тишины (VAD pause threshold). Люди с нарушениями дикции или темпа речи сталкиваются с тем, что система обрывает запись посреди фразы.

### 3.2. Незрячие пользователи (Screen Reader Users — Orca, NVDA, JAWS, VoiceOver)

#### Что уже реализовано хорошо:

- В чате есть компонент [`ChatResponseAnnouncer.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/chat/ChatResponseAnnouncer.vue) с атрибутами `role="status" aria-atomic="true" class="sr-only"`, озвучивающий ответы ИИ после окончания генерации.
- Компонент [`IconButton.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/common/IconButton.vue) принимает обязательный параметр `label` и проставляет `:aria-label="label"`.

#### Выявленные проблемы и риски:

1. **Полное отсутствие звуковой индикации (Earcons / Sound Cues):**
   - При старте и остановке захвата микрофона в приложении нет ни одного системного или программного звукового сигнала. Незрячий пользователь, активировав хоткей из чужой программы, не получает подтверждения, что микрофон открыт и слушает.
2. **Отсутствие `aria-live` в потоковой транскрипции ([`LiveTranscript.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/voice/LiveTranscript.vue)):**
   - Контейнер живой транскрипции не имеет `aria-live="polite"` или `role="status"`. Промежуточные гипотезы и распознанный текст не озвучиваются скринридером.
3. **Поля ввода без доступных меток (Accessible Name):**
   - Главные поля ввода быстрого окна ([`QuickOverlay.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/quick/QuickOverlay.vue)) полагаются только на атрибут `placeholder`. У них нет связанных элементов `<label>` или атрибута `aria-label`.
   - В чате скрытый элемент `<input type="file">` не имеет доступного имени.
4. **Специфика WebKitGTK / AT-SPI на Linux:**
   - В Tauri при создании безрамочного прозрачного окна `quick` (через layer-shell или override-redirect) окно может не передаваться в дерево AT-SPI как активное окно верхнего уровня. Orca при этом не объявляет появление окна и не переносит в него фокус чтения.
5. **Возврат фокуса ОС при закрытии оверлея:**
   - После выполнения команды или нажатия `Escape` необходимо гарантировать восстановление фокуса в исходное окно ОС. При потере фокуса скринридер прекращает озвучивание контекста пользователя.

### 3.3. Слабовидящие пользователи (Low Vision, Contrast, UI Scale)

#### Что уже реализовано хорошо:

- В приложении есть специализированный файл [`accessibility.css`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/assets/styles/accessibility.css), содержащий токены для высокой контрастности (`data-contrast="more"`) и режима принудительных цветов (`@media (forced-colors: active)`).
- Доступна настройка масштабирования интерфейса ([`SettingsAccessibilityTab.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/settings/SettingsAccessibilityTab.vue)).
- Автоматизированный тест при масштабе **200%** показал отсутствие паразитной горизонтальной прокрутки документа (`hasHorizontalScroll: false`), верстка адаптируется корректно.

#### Выявленные проблемы и риски:

1. **Критически низкая контрастность в теме E-ink (нарушение WCAG 1.4.3 AA/AAA):**
   - В теме E-ink кнопки опасных действий (`.btn-error` / `danger`) используют цвет текста `oklab(0.52 ...)` на фоне `oklab(0.50 ...)`. Разница светлоты $\Delta L \approx 0.02$. Текст на кнопке опасного действия практически неразличим для глаза.
2. **Контрастность второстепенного текста (`--app-text-faint`):**
   - В стандартной светлой теме подсказки и подписи с классом faint имеют коэффициент контрастности около 2.8:1 к фону, что ниже минимального порога WCAG AA (4.5:1 для обычного текста).
3. **Пунктирные границы пустых слотов:**
   - В лаунчере пустые слоты отрисованы полупрозрачными рамками. При слабом зрении и ярком внешнем освещении сетка слотов сливается с фоном.

### 3.4. Пользователи с нейроотличиями, когнитивными особенностями и СДВГ

#### Что уже реализовано хорошо:

- Поддерживается режим уменьшения движения (`data-motion="reduce"`), отключающий анимации и переходы.
- В быстром окне реализовано автосохранение черновика при случайном закрытии (`recalls a discarded draft when the quick window opens again`), что снижает стресс при потере фокуса.

#### Выявленные проблемы и риски:

1. **Отсутствие быстрого отката вставки (Undo/Revert):**
   - Если голосовая команда или AI-генерация вставила неверный текст в активное приложение, TyCo не предоставляет быстрого механизма отката последней вставки.
2. **Визуальный шум анимации звуковой волны:**
   - Компонент [`AudioWaveform.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/voice/AudioWaveform.vue) во время записи постоянно пульсирует. В режиме `data-motion="reduce"` волна должна переключаться в простой статический уровень, чтобы не отвлекать пользователя.

## 5. Дорожная карта устранения проблем (Actionable Roadmap)

### Этап 1. Устранение критических блокировок (Спринт быстрых исправлений)

1. **Разблокировать Tab в [`ShortcutList.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/overlay/ShortcutList.vue):**
   - Перестать перехватывать системный `Tab`. Если требуется переход в редактор, назначить для этого отдельную явную комбинацию (например, `Ctrl+E` или стрелку вправо при фокусе на последнем элементе), сохранив стандартный цикл табуляции.
2. **Добавить `:focus-visible` в [`ShortcutButton.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/overlay/ShortcutButton.vue):**
   - Добавить явное правило:
     ```css
     .shortcut:focus-visible {
       outline: var(--app-focus-outline-width) solid var(--color-primary);
       outline-offset: 2px;
     }
     ```
3. **Исправить контраст кнопок в теме E-ink ([`themes.css`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/assets/styles/themes.css)):**
   - Скорректировать цвет текста или фона для кнопок ошибки (`.btn-error`), обеспечив соотношение контраста не менее 7:1 в монохромном режиме.
4. **Добавить доступные имена для основных полей:**
   - В [`QuickOverlay.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/quick/QuickOverlay.vue) добавить `:aria-label="t('quick.inputPlaceholder')"` к `<textarea>`.

### Этап 2. Поддержка незрячих пользователей и звуковой фидбек

1. **Внедрить звуковые подсказки (Earcons):**
   - Добавить в Rust-бэкенд или вебвью генерацию коротких ненавязчивых звуков (бипов Web Audio API или системных bell/canberra) при начале записи, окончании записи и ошибке.
   - Вынести переключатель в [`SettingsAccessibilityTab.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/settings/SettingsAccessibilityTab.vue): `Звуковое подтверждение голосовых команд`.
2. **Оснастить транскрипцию живыми регионами:**
   - В [`LiveTranscript.vue`](file:///mnt/disk2/codeWorkspace/tyco/apps/desktop-ui/src/components/voice/LiveTranscript.vue) добавить на контейнер `role="status" aria-live="polite" aria-atomic="false"`.

### Этап 3. Продвинутая клавиатурная навигация и гибкость

1. **Стрелочная навигация в сетке команд:**
   - Реализовать композитную навигацию (Roving Tabindex) со стрелками Вверх/Вниз/Влево/Вправо по сетке 5x3.
2. **Настройка чувствительности пауз (VAD):**
   - Добавить в настройки голоса параметр `Задержка автозавершения речи (мс)` для комфортной диктовки людьми с медленным темпом речи.
3. **Глобальный откат (Undo):**
   - Реализовать хоткей или команду отката последней вставки текста в целевое приложение.
