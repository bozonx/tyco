# Активация по хоткею: архитектура и оставшиеся задачи

Продолжение `dev_docs/quick-input-plan.md`. Тот план отвечал на вопрос
«как не терять символы»; этот — на вопрос «как окно вообще вызывается»
и «как это разложить, чтобы потом лёг Windows и macOS».

Шаг 2 исходного плана (поле быстрого ввода вне роутера) выполнен, см. раздел
«Что уже сделано». Остальное — ниже, в порядке, в котором имеет смысл делать.

## Принятые решения

### Одно окно, два профиля геометрии

Окно остаётся одно (`main`). Второе окно означало бы второй webview, а вместе
с ним вторую загрузку локальных моделей LLM и Whisper — они живут в webview
через transformers.js. Это дороже, чем неудобство общего окна.

Вместо двух окон — два профиля геометрии одной поверхности:

| Профиль | Режимы                              | Геометрия                                                               |
| ------- | ----------------------------------- | ----------------------------------------------------------------------- |
| `panel` | editor / write / voice / correction | layer-shell: anchor bottom, полупрозрачная полоса, без рамки и таскбара |
| `sheet` | history / config / chat             | та же поверхность, anchor снят (композитор центрует), размер больше     |

`gtk_layer_init_for_window` вызывается один раз в `setup()`, до первого показа.
Профиль применяется в момент активации, **до** `window.show()`, пока окно
скрыто. Фолбэк без layer-shell (GNOME/Mutter, X11) — `set_size` + `set_position`.

Следствие: `decorations: false` навсегда, значит для `sheet` придётся рисовать
свой заголовок и перетаскивание во фронтенде.

### Захват хоткея — платформенный, доставка сигнала — общая

Кросс-платформенного способа поймать глобальный хоткей, который работает
на Wayland, не существует: `tauri-plugin-global-shortcut` под капотом делает
X11-грабы, и в нативной Wayland-сессии нажатия до него не доходят. Поэтому
захват — трейт с несколькими реализациями, а всё, что после него, — общее.

Все пути сходятся в одну функцию `runtime::activate(app, Activation)`.

| Транспорт                                             | Когда                                                | Порядок задержки |
| ----------------------------------------------------- | ---------------------------------------------------- | ---------------- |
| Хоткей в самом процессе (portal / `global-shortcut`)  | основной путь                                        | ~0               |
| D-Bus `org.tyco.Interface.SwitchMode`                 | внешняя автоматизация, запас, если портал не завёлся | единицы мс       |
| Тонкий CLI `tyco-ctl` через локальный сокет           | кросс-платформенная автоматизация                    | единицы мс       |
| Аргументы основного бинарника через `single-instance` | холодный старт                                       | сотни мс         |

Запуск второго экземпляра основного бинарника тянет за собой загрузку GTK
и webkit только ради того, чтобы передать аргументы и умереть. Эти сотни
миллисекунд ложатся **до** `show()` — ровно в тот промежуток, который в отчёте
измерялся как потерянные символы. Поэтому это путь холодного старта, а не
основной. `tyco-ctl` — отдельный крошечный крейт воркспейса, не линкующий
ни GTK, ни webkit.

### Два класса вызова

- `keyboard-first` (editor, write, chat) — окно обязано забрать клавиатуру
  немедленно, `keyboard_mode = Exclusive`. Ради этого прогрев и постоянно
  смонтированное поле.
- `context-first` (correction, aiTasks, voice, select) — исходник берётся
  из выделения, пользователь не печатает. Панель показывается
  с `keyboard_mode = None`, не отбирая клавиатуру у исходного окна.

`START_MODES` сейчас этого не различает, и режима `correction` в нём нет
вовсе — есть только `CorrectionMenu`. Его нужно завести как полноценный режим
активации.

## Что уже сделано

Шаг 2 исходного плана: поле быстрого ввода вынесено из `RouterView`.

- `components/QuickPanel.vue` смонтирован в `App.vue` всегда, видимость
  переключается через `v-show`; CodeMirror создаётся один раз за жизнь приложения.
- Маршрут `/editor` остался routable, но рендерит пустую заглушку
  `views/quick-panel-host-view.ts`. Благодаря этому `appNavigation.goToEditor()`,
  `isCurrent(EDITOR.path)` и `routeParamsStore.isEditorPage()` работают как
  раньше, без правок в вызывающем коде.
- `lib/quick-panel/quick-panel.ts` — DI-модель входа и выхода из панели.
  Вход: применить параметры навбара и вернуть фокус в поле. Выход: сбросить
  ввод в историю. Раньше это висело на `onMounted`/`onUnmounted` вью и
  компонента `Editor.vue`, а теперь монтирования нет.
- Фокус возвращается в поле и при **скрытии** окна: к следующему показу
  сфокусированный элемент в DOM уже существует, и клавиатуре не надо его ждать.
- `stores/quickPanel.ts` — тонкий стор, связывающий модель со сторами ввода,
  истории, навбара и модалок. Модель покрыта юнит-тестами.

## Задача 1. Прогрев окна при старте

Шаг 1 исходного плана, не сделан. В `services/runtime.rs`, в `setup()`,
отложенным потоком прогнать 3 цикла `show`/`hide` с паузой 250 мс, через 400 мс
после старта. Образец — `LAB_WARMUP` в `prototypes/tauri-quick/src/main.rs`.

Прогрев не должен трогать состояние: нынешний `show_main_window` пишет
`params.mode` и `is_window_shown` и шлёт `emit_params`. Нужен отдельный путь,
только `window.show()` / `window.hide()`, без `AppState` и без событий
во фронтенд.

Критерий: первый вызов по хоткею после запуска не теряет символов.

Открытый вопрос: достаточно ли одного маппинга без реального фокуса. Если да —
мигание при старте убирается. Проверяется в лаборатории до переноса.

## Задача 2. Единая точка активации

Сейчас показ размазан по трём местам: `runtime::show_main_window`, обработчик
`switch_mode` в `services/dbus.rs` (который поверх `show_main_window` ещё раз
делает `show` и `set_focus`), и трей. Свести в одну функцию:

```rust
pub struct Activation {
    pub mode: StartMode,
    pub intent: ActivationIntent,   // KeyboardFirst | ContextFirst
    pub source: ActivationSource,   // Hotkey | Dbus | Cli | Tray
}

pub fn activate(app: &AppHandle, activation: Activation) -> Result<(), AppError>
```

Порядок внутри важен: применить профиль геометрии, показать окно, и только
потом — всё остальное. Разобрать аргументы командной строки в обработчике
`single_instance` (`src-tauri/src/lib.rs:62`, сейчас там `_args`).

## Задача 3. Контекст вызова снимать после показа

`run-ui.sh` перед D-Bus вызовом запускает `xdotool getactivewindow` и `xclip`.
Два процесса на критическом пути, до того как окно начало показываться.

Правильно: `activate()` показывает окно, а `window_id` и выделенный текст
снимает отдельным потоком и досылает во фронтенд событием. К моменту, когда
контекст готов, пользователь уже печатает.

Трейт `ForegroundContext { fn capture() -> CallContext }`: на X11 — xdotool,
на Wayland — только PRIMARY через `wl-paste`, `window_id` там нет и не будет.

## Задача 4. Провайдеры хоткеев

Трейт `HotkeyProvider`, реализация выбирается в рантайме по сессии
(`XDG_SESSION_TYPE`), а не по `cfg!`:

1. **XDG portal `org.freedesktop.portal.GlobalShortcuts`** — Linux Wayland.
   KDE Plasma 6 реализует, GNOME — начиная с 48. Привязку подтверждает
   пользователь в системных настройках, приложение только предлагает триггеры.
   **Проверить до того, как закладываться**: требуется `.desktop` с app id,
   совпадающим с идентификатором приложения, и для не-flatpak сборки это
   работает не везде.
2. **`tauri-plugin-global-shortcut`** — X11, Windows, macOS.
3. **Внешний триггер** — уже существующий D-Bus, остаётся всегда.

Привязки хранятся в `userConfig`, настраиваются в UI. Пока провайдер 1
не проверен — рабочим остаётся D-Bus плюс бинд в настройках WM.

## Задача 5. layer-shell и профили геометрии

Шаг 3 исходного плана, расширенный до двух профилей.

- В `tauri.conf.json` для окна `main`: `transparent: true`,
  `decorations: false`, `skipTaskbar: true`.
- Новый модуль по образцу `prototypes/tauri-quick/src/layer.rs`: шесть функций
  системной `libgtk-layer-shell` через `extern "C"`, без отдельного крейта.
  Линковка — строкой в `build.rs`. Сборочная зависимость `gtk-layer-shell`
  добавляется в требования в README.
- Вызов из `setup()` до первого показа окна. Профиль (`panel` / `sheet`)
  применяется в `activate()` до `show()`.
- Клавиатура переключается между `None` и `Exclusive` по `intent` вызова.
- Откат: `gtk_layer_is_supported()` возвращает false на GNOME — там обычное
  окно. Молчаливая деградация, не ошибка запуска.

После этого шага activation token не нужен — но только на композиторах
с layer-shell.

## Задача 6. UI профиля `sheet`

Следствие `decorations: false`: для истории, настроек и чата нужны свой
заголовок, кнопка закрытия и область перетаскивания (`data-tauri-drag-region`).
Плюс компактная вёрстка `panel`: сейчас `QuickPanel` рассчитан на окно 800×600,
а не на полосу внизу экрана.

## Задача 7. Повторный замер на настоящем UI

Шаг 4 исходного плана. Лаборатория гоняла голый HTML; boot Vue, pinia и i18n
добавят своё время.

Прокинуть в приложение метки t0-t5 и команды `show`/`result`
из `prototypes/tauri-quick/src/metrics.rs` и `src/ipc.rs`, под флагом сборки
или переменной окружения. Бенч `prototypes/tauri-quick/examples/bench.rs`
переиспользуется как есть.

Критерий: 20 попыток подряд, задержка первой клавиши 100 мс, пауза между
вызовами 10 с — ноль потерянных символов. Замер повторить на release-сборке:
все цифры отчёта получены в debug.

## Задача 8. Вставка обратно в исходное окно

Шаг 5 исходного плана. `src-tauri/src/commands/window.rs:39` по умолчанию
использует `xdotool`, который работает только на X11. Нужен `ydotool`
(с правами на uinput) либо `zwp_virtual_keyboard`.

Там же два `thread::sleep(300)` (строки 52 и 68) — гонка того же класса,
что чинилась в задачах 1 и 3, только в обратную сторону: правильнее ждать
события фокуса, а не спать.

Приятное следствие задачи 5: layer-поверхность не становится «активным окном»
в понимании композитора, поэтому исходный toplevel остаётся активным
и переактивировать его по `window_id` не нужно.

## Задача 9. Слой `platform/`

Собрать платформенные реализации в `src-tauri/src/platform/{linux,windows,macos}`
за четырьмя трейтами. Выбор — в `setup()`. Фронтенд о платформе не знает
ничего: он получает `mode` и `intent`.

| Трейт                                         | Linux                    | Windows                     | macOS                                 |
| --------------------------------------------- | ------------------------ | --------------------------- | ------------------------------------- |
| `PanelSurface` (геометрия, захват клавиатуры) | gtk-layer-shell / фолбэк | `WS_EX_NOACTIVATE`, topmost | `tauri-nspanel`, `NonactivatingPanel` |
| `HotkeyProvider`                              | portal / global-shortcut | global-shortcut             | global-shortcut + Accessibility       |
| `ForegroundContext`                           | xdotool / wl-paste       | `GetForegroundWindow`       | Accessibility API                     |
| `TextInjector`                                | ydotool / xdotool        | `SendInput`                 | `CGEvent`                             |
