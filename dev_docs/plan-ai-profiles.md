Статус: планирование архитектуры и реализации.  
Дата: 2026-10-15  
Стек: Vue 3, Pinia, TypeScript, Rust (Tauri 2), Vercel AI SDK (`@bozonx/ai-kit`, `@ai-sdk/*`).

## 1. Концепция и ключевые требования

Фича «Профили ИИ» предоставляет изолированные рабочие контексты (агенты/профили) для работы с текстами и файлами проектов. Это не автономные агенты (нет фоновых фоновых задач без пользователя), а специализированные чат-ассистенты, каждый со своей персоной (`SOUL.md`), отдельной историей и разграниченным доступом к файловой системе.

### Основные требования:

1. **Базовый чат**: Текущий глобальный чат переименовывается в **«Спросить у ИИ»** (Ask AI). Это легковесный базовый чат без привязки к `SOUL.md`, рабочей папке и проектам.
2. **Сессии профиля (Вариант А)**: Внутри одного профиля может быть множество независимых веток чатов (сессий), но все они используют единый `SOUL.md`, общую рабочую папку профиля и настройки прав.
3. **Файловая структура и переносимость (Git-friendly)**:
   - Все сущности хранятся в виде обычных файлов и папок (JSON, Markdown), что позволяет инициализировать там Git-репозиторий или синхронизировать каталог через облако.
   - В настройках доступна опция **«Путь к рабочей папке профилей»** (по умолчанию в данных Tyco `app_data_dir/ai-vault`, но можно указать любую директорию на диске).
   - В папке каждого профиля находятся: `profile.json`, `SOUL.md` (системный промпт), `history/` (сохранённые сессии), `workspace/` (домашняя папка агента без ограничений с подпапками `uploads/`, `generated/`, `downloads/`).
4. **Проекты и матрица прав**:
   - Общая папка `projects/` с подпапками проектов, а также возможность подключать внешние папки на диске в качестве проектов.
   - Разграничение прав для каждого профиля к каждому проекту: раздельно на **Чтение** (`read`) и **Запись** (`write`) со значениями:
     - `deny` (запрещено);
     - `ask` (спрашивать каждый раз);
     - `allow` (полностью разрешено).
5. **Интерфейс настроек**:
   - Вкладка **«ИИ профили»** в `Settings.vue`.
   - В боковом меню `NavigationList` пункт «ИИ профили» содержит вложенное подменю (`nested: true`) со списками созданных профилей и проектов.
   - Редактирование `SOUL.md` в интерфейсе выполняется через стандартное многострочное текстовое поле (`textarea`).
6. **Топбар приложения**:
   - В `NavPanel.vue` после кнопки «Спросить у ИИ» размещается разделитель, а затем табы созданных пользователем профилей.
   - При большом количестве профилей включается аккуратный **горизонтальный скролл** блока табов профилей.
7. **Выбор модели LLM**:
   - Модель выбирается пользователем динамически в чате или подтягивается ранее установленная (сохранение последней использованной модели для профиля).

## 2. Схема хранения данных на диске

```text
<ai_vault_root>/
├── profiles/
│   ├── {profile-id}/
│   │   ├── profile.json       # Метаданные профиля и таблица прав
│   │   ├── SOUL.md            # Системный промпт / персона / правила
│   │   ├── history/           # Сессии диалогов этого профиля
│   │   │   ├── index.json     # Индекс сессий профиля
│   │   │   └── {chat-id}.json # Сообщения конкретной сессии
│   │   └── workspace/         # Домашняя папка (доступ без подтверждения)
│   │       ├── uploads/       # Файлы, переданные пользователем
│   │       ├── generated/     # Сгенерированные файлы
│   │       └── downloads/     # Скачанные файлы
├── projects/
│   ├── {project-id}/
│   │   ├── project.json       # Метаданные (id, name, isExternal, targetPath)
│   │   └── files...           # Файлы внутреннего проекта (если не external)
```

### Формат `profile.json`:

```json
{
  "id": "tech-writer",
  "name": "Технический писатель",
  "modelId": "anthropic:claude-3-5-sonnet",
  "temperature": 0.4,
  "maxOutputTokens": 2048,
  "projectPermissions": {
    "core-app": { "read": "allow", "write": "ask" },
    "external-docs": { "read": "allow", "write": "deny" }
  },
  "createdAt": 1740000000000,
  "updatedAt": 1740000000000
}
```

### Формат `project.json`:

```json
{
  "id": "core-app",
  "name": "Основное приложение",
  "description": "Исходники и документация",
  "isExternal": false,
  "targetPath": null,
  "createdAt": 1740000000000
}
```

### 2.1. Контракты и интерфейсы (`packages/shared`)

Создать модуль `packages/shared/src/ai-profiles.ts`:

```typescript
export type ProjectAccessMode = 'allow' | 'ask' | 'deny'

export interface ProjectPermission {
  read: ProjectAccessMode
  write: ProjectAccessMode
}

export interface AiProfile {
  id: string
  name: string
  icon?: string
  lastModelId?: string
  projectPermissions: Record<string, ProjectPermission>
  createdAt: number
  updatedAt: number
}

export interface AiProject {
  id: string
  name: string
  description?: string
  isExternal: boolean
  targetPath?: string
  createdAt: number
  updatedAt: number
}

export interface AiVaultConfig {
  vaultPath?: string
}
```

## 5. Уточнения после ревью (2026-10-16)

- **Граница с «Спросить у ИИ»**: у каждого профиля свой экземпляр чат-store
  (`useProfileChatStore(profileId)`) и свой черновик ввода. Принадлежность чата
  задаётся экземпляром, а не текущим маршрутом: уход в настройки или редактор не
  останавливает генерацию и не переносит чат в другой контекст. Внутри экрана
  чата нужный store передаётся через `provideChatScope` / `useChatScope`.
  Профили и обычный чат никак не связаны: текст из редактора, AI-задачи и
  быстрое окно работают только со «Спросить у ИИ».
- **SOUL.md — корневая инструкция профиля**: системная инструкция и правила
  пользователя для обычного чата к профилю не применяются. `SOUL.md` и
  `profile.json` перечитываются перед каждым запросом.
- **Параметры генерации** (`modelId`, `temperature`, `maxOutputTokens`) задаются
  в настройках профиля; выбор модели в чате профиля меняет `modelId` профиля и
  не трогает модель обычного чата. Старый `lastModelId` читается как `modelId`.
- **Хранение чатов профиля** идёт через тот же код, что и у обычного чата
  (`services/storage/chat_history.rs` с параметром папки): журнал транзакций,
  блокировка, карантин, картинки в `history/images`, политика истории
  (выключенная история не сохраняет и чаты профилей). Команды чатов принимают
  необязательный `profileId`.
- **Настройки профиля** сохраняются автоматически; иконки у профилей нет.
  `create_ai_profile` не перезаписывает существующий профиль, `save_ai_profile`
  не воскрешает удалённый. Недоступный настроенный путь хранилища — ошибка, а
  не тихий переход на путь по умолчанию.
- **Проекты и права** скрыты флагом `IS_AI_PROJECTS_ENABLED` до появления
  инструментов; профиль без записи о проекте не имеет к нему доступа (`deny`).
