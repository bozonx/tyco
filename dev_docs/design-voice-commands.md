# Голосовые команды — дизайн-документ

Статус: принятые решения, к реализации не приступали.
Дата: 2026-10-03

## 1. Цель

Пользователь нажимает отдельный хоткей, произносит команду, и приложение
выполняет действие: создаёт заметку, отправляет сообщение, вызывает скрипт или
вебхук и т. д.

Голосовые команды полезнее всего, когда фраза несёт и **выбор команды**, и
**аргумент**:

- «Запиши в блокнот: купить молоко»
- «Отправь в телеграм: буду через десять минут»
- «Напомни через час позвонить маме»

Команды без аргумента («запусти бэкап») тоже поддерживаются, но для них голос
почти не выигрывает у хоткея.

## 2. Принятые решения

### 2.1. Отдельный режим с отдельным хоткеем

Голосовые команды — отдельное быстрое действие, а не часть голосовой диктовки.

Почему: в диктовке приходится решать две задачи. Первая — «это команда или
текст». Вторая — «какая именно команда». Вторая решается надёжно. Первая —
нет, а цена ошибки высока: фраза «сделай вывод по отчёту» в обычном тексте не
должна запускать shell-скрипт. В отдельном режиме первой задачи нет вовсе: всё,
что сказано после хоткея, считается командой.

Слова-триггеры («сделай», «выполни», «запусти», «Тайко») в этом режиме не
обязательны. Если они есть в начале фразы, распознаватель их отбрасывает.

Встраивать команды в диктовку («Тайко, …» в начале высказывания) можно
рассмотреть позже, как отдельную опцию, только с обязательным подтверждением
(см. §11).

### 2.2. Команды форматирования диктовки — отдельная тема

«Новая строка» и «новый абзац» внутри диктовки — это другой класс команд. Они
не проходят через распознавание намерений: у них фиксированный маленький
словарь, точное совпадение и срабатывание только отдельным сегментом (пауза до
и после). Проговаривать знаки препинания («точка», «запятая») не нужно:
пунктуацию расставляют STT-провайдер и LLM-коррекция. В этот документ они не
входят.

### 2.3. Тип команды и экземпляр команды

Две сущности:

- **Тип команды (обработчик)** — что команда умеет. Его предоставляет ядро или
  плагин: схема настроек, нужен ли аргумент, функция выполнения.
- **Экземпляр команды** — то, что создаёт пользователь: название, фразы для
  распознавания, выбранный тип, заполненные настройки этого типа, флаг
  подтверждения.

Из одного типа можно сделать несколько команд с разными настройками:

| Команда         | Фразы                                 | Тип              | Настройки                        |
| --------------- | ------------------------------------- | ---------------- | -------------------------------- |
| Рабочая заметка | «запиши в рабочий», «рабочая заметка» | `fastNote.write` | папка `~/work`, дописать в daily |
| Идея            | «запиши идею», «идея»                 | `fastNote.write` | папка `~/ideas`, новый файл      |
| Бэкап           | «запусти бэкап», «сделай бэкап»       | `script`         | `~/bin/backup.sh`                |

Распознаватель видит плоский список экземпляров с фразами и не знает, откуда
взялся тип.

### 2.4. Источники типов: встроенные и плагины

- **Встроенные:** `script` и `webhook`. Это тот же код, что сейчас выполняет
  пользовательские действия в меню (`lib/action-menu/custom-actions.ts`,
  `src-tauri/src/services/custom_actions.rs`). Его выносим в общий модуль, а не
  дублируем.
- **Плагины** регистрируют свои типы через `PluginContext` (см. §4).

Script и webhook — «запасной выход»: всё, для чего нет плагина, пользователь
делает скриптом, который может вызвать любую CLI или API.

### 2.5. Единый обработчик для действий и команд

Тип команды и пункт меню действий — это одно и то же «действие над текстом».
Разница только в источнике текста: действие меню берёт его из редактора,
голосовая команда — из аргумента фразы. Цель — чтобы плагин описывал
обработчик один раз, и тот работал в обоих местах. Пока регистрации остаются
раздельными, но исполнители script/webhook общие с первого этапа.

### 2.6. Плагины встроенные, установки в рантайме нет

Плагины по-прежнему вкомпилированы в сборку (`apps/desktop-ui/src/plugins.ts`).
Сторонние JS-плагины в рантайме не загружаем:

- CSP запрещает inline- и динамические скрипты (`script-src`), а ослаблять её
  не хотим;
- чужой код в webview получает доступ к IPC; изоляция (iframe/worker с узким
  API) — отдельный большой проект.

Расширяемость сторонними интеграциями в будущем — через MCP-серверы (§11):
это отдельные процессы, ими управляет Rust, и CSP webview они не затрагивают.

### 2.7. Распознавание: фразы, нечёткое сопоставление, LLM как запасной вариант

- У каждой команды есть **несколько фраз**. Пользователь не обязан помнить
  точное название.
- **Уровень 1 — локальное нечёткое сопоставление.** Работает без сети,
  мгновенно, детерминированно.
- **Уровень 2 — LLM-классификатор**, вызывается только когда первый уровень
  не уверен. Использует существующий `lib/llm` со структурированным ответом:
  выбор из enum id команд плюс `none`.
- Классификатор спрятан за интерфейсом `IntentClassifier`. Jev от TypeSafe AI
  (типизированные решения с калиброванной уверенностью) концептуально
  подходит, но пока доступен только в раннем доступе и только в облаке. Его
  можно добавить второй реализацией позже, без изменения остального кода.
- Если LLM не настроена или нет сети, работает только первый уровень.

### 2.8. Подтверждение вместо угадывания

Решение зависит от уверенности:

- высокая и однозначная → выполнить;
- средняя или два близких кандидата → показать подтверждение;
- низкая или `none` → показать список команд с поиском.

У экземпляра команды есть флаг `confirm: 'auto' | 'always'`. Для типа `script`
по умолчанию `always`: действие нельзя отменить.

## 3. Модель данных

`packages/shared/src/user-config.ts`:

```ts
export interface VoiceCommandConfig {
  id: string
  name: string
  /** Phrases that select this command; the name is matched as well */
  phrases: string[]
  /** `script`, `webhook`, or `<pluginName>.<localTypeId>` */
  typeId: string
  /** Values for the type's config fields */
  typeConfig: Record<string, unknown>
  confirm: 'auto' | 'always'
  enabled: boolean
}

export interface VoiceCommandsSettings {
  commands: VoiceCommandConfig[]
  /** Leading words stripped before matching, per UI language */
  triggerWords: string[]
  /** Use the LLM when local matching is not confident */
  llmFallback: boolean
}
```

Хоткей режима хранится вместе с остальными глобальными хоткеями
(`UserConfig.hotkeys`), под отдельным id действия `voiceCommand`.

Конфиг встроенных типов совпадает с полями `ScriptMainAction` и
`WebhookMainAction` (без `id`/`name`), чтобы общий редактор работал в обоих
местах.

## 4. API для плагинов

`apps/desktop-ui/src/types/plugins.ts`:

```ts
export interface VoiceCommandType {
  /** Local to the plugin; the full id becomes `<pluginName>.<id>` */
  id: string
  labelKey?: string
  label?: string
  icon?: string
  /** Whether the spoken phrase carries text for the command */
  argument: 'none' | 'text'
  /** Rendered in the command editor, same format as plugin settings */
  configFields?: InputConfigItem[]
  /** Phrases suggested when the user creates a command of this type */
  defaultPhrasesKey?: string
  run(input: VoiceCommandInput): Promise<VoiceCommandResult>
}

export interface VoiceCommandInput {
  argument: string
  config: Record<string, unknown>
  signal: AbortSignal
}

export interface VoiceCommandResult {
  ok: boolean
  /** Shown in the toast; i18n key or plain text */
  messageKey?: string
  message?: string
}

export interface PluginContext {
  // ...existing members
  registerVoiceCommandTypes(types: VoiceCommandType[]): void
}
```

Позже `argument` расширяется до структурированного аргумента
(`{ kind: 'schema', schema }`) для команд вроде напоминаний (время + текст). Их
поля заполняет LLM. В первую версию это не входит.

Если плагин отключён, его экземпляры команд остаются в конфиге, но в списке
помечаются как недоступные и не участвуют в распознавании.

## 5. Распознавание

Вход — финальный текст от STT. Шаги:

1. **Нормализация:** нижний регистр, `ё → е`, убрать пунктуацию, схлопнуть
   пробелы.
2. **Отбросить слова-триггеры** в начале фразы («сделай», «выполни»,
   «запусти», «Тайко» и их варианты, которые выдаёт STT).
3. **Сопоставление по префиксу.** Для каждой фразы каждой команды ищем, насколько
   хорошо начало высказывания совпадает с фразой (по токенам, с допуском на
   окончания и опечатки: Левенштейн по токенам или триграммы). Остаток после
   совпавшего префикса — аргумент.
4. **Оценка:** лучший кандидат, его score и отрыв от второго.
5. **Решение** по порогам (§2.8). Если уверенности не хватает и
   `llmFallback` включён:
6. **LLM-классификатор.** В промпт идут id, названия, фразы и тип аргумента
   команд. Ответ: `{ commandId: <enum ids | "none">, argument: string,
confidence: number }`. Ответ вне схемы считается `none`.

Пороги подбираются по тестовой таблице фраз (юнит-тесты matcher). Для команд с
`argument: 'none'` остаток должен быть пустым или очень коротким: иначе это,
скорее всего, другая команда.

**Проверки в настройках:**

- предупреждение, если одна фраза (после нормализации) есть у двух команд;
- предупреждение, если фраза одной команды — префикс фразы другой.

**Обучение на подтверждениях (опционально):** если пользователь подтвердил
команду для непредусмотренной формулировки, предложить добавить её в фразы.

## 6. Пользовательский поток

1. Хоткей → открывается компактный оверлей с индикатором записи и живым
   транскриптом (переиспользуем `voice-session` / `live-dictation`).
2. Остановка записи: повторное нажатие хоткея, Enter или пауза (настраивается).
3. Распознавание (§5). Оверлей показывает выбранную команду и аргумент.
4. Если нужно подтверждение: Enter — выполнить, Esc — отмена, стрелки — другой
   кандидат. Аргумент можно поправить с клавиатуры перед выполнением.
5. Выполнение, тост с результатом, оверлей закрывается.

Ошибки: нет STT-ключа или сети → понятное сообщение и ссылка в настройки.
Команда не найдена → список команд с поиском, транскрипт сохраняется.

Каждое выполнение записывается в историю (фраза, команда, аргумент,
результат), чтобы было видно, почему сработала та или иная команда.

## 7. Настройки

Новая вкладка в блоке действий: «Голосовые команды».

- Список команд: название, фразы, тип, включена ли. Порядок меняется
  перетаскиванием (`lib/sortable`).
- Редактор команды: название, фразы (список тегов), выбор типа, поля типа,
  подтверждение.
- Для `script` и `webhook` — тот же компонент редактора, что во вкладке
  основных действий (выносится в общий компонент).
- Общие параметры: слова-триггеры, LLM как запасной вариант, хоткей.
- Кнопка «Проверить фразу»: ввести текст и увидеть, какая команда выберется и
  с каким score. Без запуска команды.

## 8. Структура кода

```
apps/desktop-ui/src/lib/
  custom-actions/            # extracted from action-menu/custom-actions.ts
    script-executor.ts
    webhook-executor.ts
  voice-commands/
    normalize.ts             # normalization, trigger word stripping
    matcher.ts               # fuzzy prefix matching, scoring
    intent-classifier.ts     # interface + LLM implementation
    resolver.ts              # thresholds, decides run / confirm / pick
    command-registry.ts      # built-in + plugin types, resolves instances
    voice-command-session.ts # capture → transcript → resolve → run
apps/desktop-ui/src/stores/voiceCommands.ts   # thin Pinia wiring
apps/desktop-ui/src/components/settings/
  SettingsVoiceCommandsTab.vue
  CustomActionEditor.vue     # shared by main actions and voice commands
```

Каждый модуль в `lib/voice-commands/` покрывается юнит-тестами. Matcher и
resolver тестируются таблицами «фраза → ожидаемая команда и аргумент» на
нескольких языках.

Rust: новых сервисов для MVP не нужно. Хоткей регистрируется существующим
механизмом `services/hotkeys.rs`, скрипты — через `custom_actions.rs`, вебхуки —
через `services/net`.

## 9. Безопасность

- `script` выполняется с правами пользователя. По умолчанию — подтверждение,
  в редакторе показывается точная команда.
- Аргумент передаётся в скрипт только через `TYCO_TEXT` и stdin, никогда не
  подставляется в строку команды (защита от инъекций через голос).
- В вебхуках аргумент подставляется в `payloadTemplate` с JSON-экранированием.
- Ключи внешних сервисов, которые нужны плагинам, хранятся в Rust-хранилище
  секретов (`services/secrets.rs`) и привязаны к origin сервиса. Плагин видит
  только `tyco-secret:<id>`.
- Плагины получают только функции из `PLUGIN_DESKTOP_FUNCTIONS`. Новые
  возможности добавляются туда явно.

## 10. Этапы

1. **Общий код действий.** Вынести исполнители script/webhook и редактор в
   общие модули, меню действий переводится на них без изменения поведения.
2. **Модель и реестр.** `VoiceCommandConfig` в shared, `VoiceCommandType`,
   `registerVoiceCommandTypes`, встроенные типы `script` и `webhook`.
3. **Распознавание.** `normalize`, `matcher`, `resolver` с тестами; без LLM.
4. **Режим и UI.** Хоткей, оверлей, подтверждение, вкладка настроек, «Проверить
   фразу».
5. **LLM как запасной вариант.** `IntentClassifier` на `lib/llm`.
6. **Первые плагинные типы:** FastNote, поиск в интернете, AI-задача/чат,
   перевод (см. §12).
7. **Плагины внешних сервисов** по спросу.

## 11. Отложено и открытые вопросы

- **Команды внутри диктовки** («Тайко, …» в начале высказывания) — только с
  подтверждением и отдельной настройкой. Нужно проверить, как STT распознаёт
  имя, и использовать подсказку ключевых слов провайдера.
- **Структурированные аргументы** (время, дата, получатель) — заполняются LLM
  по схеме типа.
- **MCP-серверы как источник типов.** Rust запускает stdio-сервер, tools
  становятся типами команд, аргументы заполняет LLM по JSON-схеме tool.
  Подтверждение обязательно. Даёт готовые интеграции (Notion, Todoist,
  календари) без собственного магазина плагинов.
- **Jev** как реализация `IntentClassifier`, когда станет общедоступен.
- **Один обработчик для меню действий и команд** (§2.5): объединить регистрацию,
  чтобы плагин объявлял тип один раз.
- **Остановка записи по паузе** — подобрать длительность и решить, нужна ли она
  по умолчанию.

## 12. Предлагаемые плагины

Порядок — по соотношению пользы и сложности.

### Первая очередь (на базе того, что уже есть)

| Плагин / тип                        | Пример фразы                       | Что делает                                                                                   |
| ----------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------- |
| **FastNote** `fastNote.write`       | «запиши в блокнот купить молоко»   | Новая заметка или дописать в существующую; пресеты Obsidian, Logseq, папки по датам уже есть |
| **SearchInInternet** `search.web`   | «найди рецепт борща»               | Открыть поиск с аргументом; настройка — поисковик                                            |
| **AI-задача / чат** `ai.ask`        | «спроси нейросеть как …»           | Открыть чат или выполнить AI-задачу с аргументом                                             |
| **Перевод** `translation.translate` | «переведи на английский я опоздаю» | Перевести и вставить или скопировать результат                                               |
| **Вставка** `text.insert`           | «напиши …»                         | Вставить аргумент в активное окно (как быстрая диктовка)                                     |

### Вторая очередь (локальные, без внешних сервисов)

| Плагин / тип              | Пример фразы                                     | Что делает                                                                                                     |
| ------------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| **Напоминания и таймеры** | «напомни через двадцать минут проверить духовку» | Локальный таймер в Rust + системное уведомление (`desktop_notifications.rs`); нужен структурированный аргумент |
| **Задачи в файле**        | «добавь задачу купить подарок»                   | Чек-лист в Markdown или `todo.txt`; работает с Obsidian/Logseq                                                 |
| **Медиа**                 | «пауза», «следующий трек»                        | Linux — MPRIS через D-Bus; позже Windows/macOS                                                                 |
| **Открыть**               | «открой браузер», «открой проект tyco»           | Запуск приложения, URL или папки из пользовательского списка                                                   |
| **Буфер обмена**          | «скопируй …»                                     | Положить аргумент в буфер обмена                                                                               |

### Третья очередь (внешние сервисы, по спросу)

| Плагин                 | Пример фразы                        | Заметки                                                |
| ---------------------- | ----------------------------------- | ------------------------------------------------------ |
| **Telegram**           | «отправь в телеграм …»              | Bot API, сообщение себе или в выбранный чат            |
| **Notion**             | «добавь в Notion в покупки молоко»  | Дописать блок на страницу или создать запись в базе    |
| **Todoist / TickTick** | «задача на завтра позвонить в банк» | REST API; дата через структурированный аргумент        |
| **Home Assistant**     | «включи свет в кабинете»            | REST API Home Assistant; сценарии из списка            |
| **Календарь**          | «встреча завтра в десять с Петей»   | CalDAV или Google Calendar; структурированный аргумент |
| **Email**              | «письмо Ивану …»                    | Черновик через `mailto:` или SMTP                      |
| **Issue-трекеры**      | «создай задачу в GitHub …»          | GitHub, GitLab, Jira                                   |

Внешние плагины ходят в сеть только через Rust-прокси (`lib/net`), ключи — в
хранилище секретов. Многие из них можно сначала закрыть вебхуком (например,
через n8n или Home Assistant), а плагин делать, когда сценарий подтвердит
полезность.
