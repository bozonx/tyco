Date: 2026-10-26. **Partial coverage; platform acceptance FAIL.** The native
paste backend works, but the UI disables its insertion action because GNOME
has no tracked `windowId`. No application fix is included in this testing change.

The UI problem is independently visible in the screenshot and source:
`InsertMenu.vue`, `use-result-actions.ts` and `EditorToolbar.vue` use the
presence of `windowId` as the insertion capability. GNOME deliberately lacks
that tracked identity. The native diagnostic proves that hiding Quick and
pasting into the focused recipient works with the same application binary.
The test does not override the disabled button or substitute IPC for a UI PASS.

Each directory contains `report.json`, frozen runner hashes/sources, native
screenshots, QMP events, source/artifact identity and guest diagnostics.
`gnome-backend-insertion.json` retains all 40 receiver observations;
`gnome-hotkey-cycles.json` retains all 20 activation observations. The final
UI failure screenshot is `20261026-093742-0f676a/VM-10.insertion.png`.
Large ignored artifacts remain local; none are committed.

Earlier failed runs are retained. They exposed preparation/fixture defects:
Ubuntu's absent `webkit2gtk-driver` package name, missing `pactl`, GTK/Cairo's
surface limit on unwrapped long receiver lines, non-atomic receiver commands,
DOM focus being insufficient before physical keys, and GNOME's ownership of
Secret Service prompt connections. The receiver now wraps long lines and
commands use atomic rename. The native focus predicate and repeated hotkey run
supersede the earlier 11-cycle result without changing the application.
Keyring creation keeps its D-Bus connection and follows both native password
fields before confirmation. These preliminary failures are not counted as
additional application defects or successful acceptance.

## Remaining acceptance gaps

GNOME is not certified. Besides the failed UI insertion action, unverified
cases include hotkey replacement/disable/conflict and RU layout, portal
cancellation/revocation and RemoteDesktop fallback without ydotool, selection
replacement degradation, browser/terminal recipients, clipboard preservation,
tray callbacks, native file dialogs/drag/drop, multi-monitor/DPI, keyring lock
and unavailable-service recovery, session lock/logout/suspend/reboot, and
production package installation/upgrade/removal. No full GNOME native suite
has passed. Targeted PASS reports do not remove these gaps.

Repository verification: `pnpm check`, Python compile checks and 30 VM runner
unit tests passed. No production Rust/IPC contract changed.
