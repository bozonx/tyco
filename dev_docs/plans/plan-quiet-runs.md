# План: тихий запуск команд извне

Статус: не начат.  
Обновлено: 2026-11-27  
Связано: `docs/external-control.md` (внешний API), `dev_docs/architecture.md`
(«Library command runs are visible and sequential», `visible_work.rs`),
`services/external/jobs.rs`, `services/status_overlay.rs`.

## Зачем

Внешние инструменты (cron, systemd timer, скрипты) запускают команды через
`tyco-ctl run`. Сейчас каждый запуск открывает оверлей и забирает фокус.
Задача по расписанию, например утренний сбор новостей, перебивает работу
пользователя. Нужен режим, в котором запуск не вмешивается в работу, но и не
скрыт: по философии проекта ничего не делается без ведома пользователя.

## Решение

Тихий или видимый запуск выбирает вызывающий флагом при вызове, а не
настройка команды. Одна и та же команда может идти из cron тихо и с хоткея
рабочего стола с окном.

- Хоткей, меню действий, голос, тулбар и `tyco-ctl run` без флага работают
  как сейчас: запуск идёт с окном.
- `tyco-ctl run <id> --quiet` и поле `quiet` в D-Bus и местном IPC (один
  диспетчер) запускают без окна и без захвата фокуса.
- Новых настроек нет. Достаточно разрешения на внешний запуск, которое уже
  выдаётся каждой команде.
- Слот запуска остаётся один (`ExternalJobs`), очереди нет.

### Тихий запуск не требует участия пользователя

Если запуску что-то нужно от пользователя, он сразу завершается ошибкой, а
не ждёт:

| Условие                                         | Результат                            |
| ----------------------------------------------- | ------------------------------------ |
| `--quiet` с `--selection` или `--replace`       | `InvalidInput` до создания job       |
| Команде нужен текст, а его нет                  | `InputRequired`, окно не открывается |
| Запуску нужно подтверждение (запрос права, ask) | новый код `ConfirmationRequired`     |

`--selection` запрещён потому, что захват нажимает клавиши копирования в
окне, где сейчас фокус. Задача по расписанию прочитала бы случайное
выделение пользователя. Действие после запуска не выполняется, как и сейчас
для внешних вызовов: результат уходит вызывающему (`--wait`).

### Тихий запуск не прерывает видимую работу

- Он не вызывает `EndVisibleWork`: диктовка, запись диалога и показанный в
  оверлее результат не трогаются.
- Он получает `Busy`, если занят слот или идёт диктовка либо запись
  диалога. Повтор делает вызывающий.
- Готовый результат в оверлее занятостью не считается: тихий запуск идёт
  рядом и оверлей не заменяет.
- Отказы `Busy` тихих запусков пользователю не показываются: повторы cron
  не должны спамить пузырями.

### Пользователь при занятом слоте

Отказ без выбора не годится, очередь тоже. Запуск пользователя ничего не
теряет: текст остаётся в редакторе, а выделение не захватывается, потому
что слот берётся до захвата. Поэтому предлагаем выбор:

> Сейчас выполняется «Сбор новостей» (внешний запуск)
> [Остановить и запустить «Перевод»] [Отмена]

- Хоткей и меню действий: показываем в оверлее, ведь окно и так открывается.
- Тулбар или редактор основного окна: тост об ошибке с кнопкой
  «Остановить и запустить».
- Задача по расписанию никогда не отменяется молча, только этой кнопкой.

### Что видно во время запуска

Окно Tyco скрыто или не в фокусе:

- Linux: существующий статус-пузырь, только информационный, без клика.
  «Выполняется: <команда>» показывается сразу, без `delayMs`, затем
  «Готово: <команда>» или «Ошибка: <команда>». Успех скрывается через
  несколько секунд, ошибка держится дольше.
- Windows: пузыря пока нет (`platform::update_status_overlay`), поэтому одно
  системное уведомление по окончании (`notifications.rs`): «Готово» или
  «Ошибка». О старте не уведомляем.

Основное окно открыто и в фокусе:

- системный пузырь не показывается;
- в шапке (`NavPanel`), рядом с кнопкой истории, стоит чип со спиннером и
  именем команды. По клику открывается поповер: что выполняется, сколько
  идёт и кнопка «Остановить» (обычная кнопка, не красная). После окончания
  чип на пару секунд показывает успех или ошибку со ссылкой «Открыть в
  истории» и исчезает.
- Тосты для хода выполнения не используем: тосты внизу справа служат для
  сбоев, а чип стоит в шапке и с ними не спорит.

### Результат: в истории

Отдельной страницы и «последнего запуска» нет. Сейчас результат внешнего
запуска в историю не попадает (`saveOutput` вызывается, только когда текст
уходит из приложения), поэтому:

- тихий запуск пишет запись в историю редактора: вход, результат или
  ошибку, команду и источник «Внешний запуск». Новое значение
  `EditorHistoryOrigin`;
- в `HISTORY_FILTERS` добавляется фильтр «Команды»;
- ошибки, отмены и таймауты попадают и в «Проблемы»;
- при выключенной истории запись не сохраняется: так настроил пользователь,
  а результат всё равно получает вызывающий;
- технический журнал `actions.log` (`log_command_run`) остаётся как есть.

## Работы

Протокол и бэкенд:

- [ ] `API_VERSION` 5; `quiet` в запросе `run` (`activation-protocol`),
      флаг `--quiet` в `tyco-ctl`, поле в D-Bus `Run`.
- [ ] Валидация: `--quiet` несовместим с `--selection` и `--replace`.
- [ ] `ErrorCode::ConfirmationRequired` (стабильный код, D-Bus-имя ошибки,
      `ALL`, выход 4 или своя группа, решить по таблице кодов выхода).
- [ ] `ExternalJobs`: признак `quiet` у job; `Busy` для тихого запуска также
      во время диктовки или записи диалога.
- [ ] `job_execution::start`: при `quiet` не вызывать `visible_work`, не
      открывать `ActivationMode::CommandRun` и не показывать окно. Job
      выполняет скрытый quick webview: определить, как он забирает тихий job
      без активации (событие и `claim_external_job`), включая
      `commandRunTimeoutSec` и сбой job при перезагрузке webview.
- [ ] Событие о состоянии тихого запуска (старт, окончание, ошибка) для
      пузыря, уведомления и чипа; `pnpm generate:desktop`.
- [ ] Linux: пузырь без задержки; не показывать, пока основное окно в
      фокусе. Windows: системное уведомление по окончании.
- [ ] Отмена тихого запуска из чипа через существующий `cancel_external_job`.

Фронтенд:

- [ ] Модель тихого запуска в `lib/commands/` (выполнение без оверлея,
      ошибки `InputRequired` и `ConfirmationRequired` вместо запросов) с
      unit-тестами; стор только связывает.
- [ ] Запись в историю: новый origin, фильтр «Команды», попадание сбоев в
      «Проблемы»; тесты `history-filter`.
- [ ] Чип и поповер в `NavPanel`; тесты компонента над `loadFakeDesktop()`.
- [ ] Выбор при занятом слоте: в оверлее для хоткея и меню, тост с действием
      для основного окна; «Остановить и запустить» отменяет тихий job и
      запускает новый.
- [ ] Ключи i18n во всех локалях (`pnpm check:i18n`).

Документация:

- [ ] `docs/external-control.md`: версия 5; `--quiet`, его
      несовместимости и ошибки; тихий запуск не завершает видимую работу;
      где видны ход и результат; пример повтора при `Busy` для cron и для
      systemd timer.
- [ ] `docs/assistant-capabilities.md`, если затронуто.
- [ ] После выполнения перенести итог в `dev_docs/architecture.md`
      (тихий запуск не скрыт: индикатор и запись в истории есть всегда,
      прервать видимую работу он не может) и удалить этот план.

  `--quiet`), чтобы фильтр «Команды» был полным, и как не задвоить записи
  с существующим `saveOutput`.
- Пузырь для Windows вместо уведомления, если понадобится паритет.

## Критерии готовности

- `pnpm validate:all` и `pnpm check:rust` без ошибок и предупреждений.
- `tyco-ctl run <id> --quiet --wait` из cron не открывает окно и не меняет
  фокус. Пока он идёт, на Linux виден пузырь, а в основном окне чип.
  Результат или ошибка есть в истории.
- Тихий запуск во время диктовки получает `Busy`, и диктовка продолжается.
- Хоткей во время тихого запуска предлагает «Остановить и запустить».
