# План: тихий запуск команд извне

Статус: не начат.  
Обновлено: 2026-11-27  
Связано: `docs/external-control.md` (внешний API), `dev_docs/architecture.md`
(«Library command runs are visible and sequential», `visible_work.rs`),
`services/external/jobs.rs`, `services/external/api/job_execution.rs`,
`services/status_overlay.rs`, `services/runtime/tray.rs`,
`stores/command-run.ts`.

## Зачем

Внешние инструменты (cron, systemd timer, скрипты) запускают команды через
`tyco-ctl run`. Сейчас каждый запуск открывает оверлей, забирает фокус и
завершает видимую работу (`EndVisibleWork`). Задача по расписанию, например
утренний сбор новостей, перебивает работу пользователя. Нужен режим, в котором
запуск не вмешивается в работу, но и не скрыт: по философии проекта ничего не
делается без ведома пользователя.

Тихий запуск не автономный агент. Его видно, пока он идёт, его можно
остановить, а итог остаётся в истории. Видимость заменяет окно, но не
пропадает.

## Решение

Тихий или видимый запуск выбирает вызывающий флагом при вызове, а не
настройка команды. Одна и та же команда может идти из cron тихо и с хоткея
рабочего стола с окном.

- Хоткей, меню действий, голос, тулбар и `tyco-ctl run` без флага работают
  как сейчас: запуск идёт с окном.
- `tyco-ctl run <id> --quiet` и поле `quiet` в D-Bus и местном IPC (один
  диспетчер) запускают без окна и без захвата фокуса.
- Новых настроек нет, нужно только разрешение на внешний запуск, которое уже
  выдаётся каждой команде. Раньше документация обещала, что каждый внешний
  запуск показывается в оверлее, поэтому текст разрешения в настройках и в
  `docs/external-control.md` меняется: команду можно запускать извне, в том
  числе без окна.

### Отдельный слот

Слот `ExternalJobs` сейчас означает «один запуск в оверлее»: голосовые
команды, команды как инструменты чата и операции редактора уже выполняются
мимо него. Тихий запуск оверлей не использует, поэтому получает свой слот:

- видимый слот: как сейчас, один запуск в оверлее (внешний видимый, хоткей,
  меню действий);
- тихий слот: один тихий запуск. Второй тихий запуск получает `Busy`, повтор
  делает вызывающий. Очереди нет.

Слоты друг друга не блокируют. Хоткей во время тихого запуска работает как
обычно, видимый внешний `run` тоже. Выбор «Остановить и запустить» не нужен.

### Тихий запуск не требует участия пользователя

Если запуску что-то нужно от пользователя, он сразу завершается ошибкой, а
не ждёт:

| Условие                                           | Результат                            |
| ------------------------------------------------- | ------------------------------------ |
| `--quiet` с `--selection` или `--replace`         | `InvalidInput` до создания job       |
| Команде нужен текст, а его нет                    | `InputRequired`, окно не открывается |
| В whitelist команды есть инструмент с `ask`       | `ConfirmationRequired` до старта     |
| Запрос права всё же возник во время запуска (ask) | `ConfirmationRequired`, job падает   |

`--selection` запрещён, потому что захват нажимает клавиши копирования в
окне, где сейчас фокус: задача по расписанию прочитала бы случайное
выделение пользователя. Действие после запуска не выполняется, как и сейчас
для внешних вызовов: результат уходит вызывающему (`--wait`).

Запрос права посреди запуска опасен: часть инструментов уже отработала,
токены потрачены. Поэтому проверка идёт до старта по whitelist команды, а
`commands describe` сообщает `canRunQuietly`, чтобы автор скрипта узнал это
заранее, а не из ночного лога. Запросы, которые возникают только по ходу
запуска, остаются второй линией защиты.

### Тихий запуск не трогает видимую работу

- Он не вызывает `EndVisibleWork`: диктовка, запись диалога и результат в
  оверлее не трогаются.
- `EndVisibleWork` от чужого запроса (`open`, видимый `run`) его не
  отменяет. Тихий запуск останавливают только кнопка «Остановить», таймаут
  `commandRunTimeoutSec`, отмена вызывающим (`jobs cancel`) и выход из
  приложения.
- Он не зависит от жизни оверлея. Сейчас запуск в оверлее кончается при
  смене режима или скрытии окна (`stores/command-run.ts`). Тихий job
  выполняется отдельной сессией, не связанной с `mode`, `isWindowShown` и
  `useVisibleWorkStore`, поэтому открытие перевода с хоткея его не прерывает.
- Диктовка и запись диалога тихому запуску не мешают: он идёт рядом, как
  команды из чата.
- Отказы `Busy` тихих запусков пользователю не показываются: повторы cron
  не должны спамить пузырями. `CommandRunRejected` для них не шлётся.

### Что видно во время запуска

Обязательный минимум на обеих платформах — индикатор в трее (рядом с
`set_tray_recording`): иконка и подсказка «Выполняется: &lt;команда&gt;» на всё
время запуска. Остальное дополняет его.

Основное окно скрыто или не в фокусе:

- Linux: существующий статус-пузырь, только информационный, без клика.
  «Выполняется: &lt;команда&gt;» показывается сразу, без `delayMs`, и скрывается
  через несколько секунд: дальше ход видно в трее. В конце «Готово:
  &lt;команда&gt;» или «Ошибка: &lt;команда&gt;»; успех скрывается через несколько
  секунд, ошибка держится дольше. Долгий запуск не держит пузырь на экране
  минутами: это мешает при демонстрации экрана и в полноэкранных
  приложениях.
- Windows: пузыря пока нет (`platform::update_status_overlay`), поэтому трей
  и одно системное уведомление по окончании (`notifications.rs`): «Готово»
  или «Ошибка». Уведомление может заглушить режим фокусировки, поэтому трей
  обязателен.
- В фокусе оверлей (пользователь в переводе, в меню действий): пузырь не
  показывается, чтобы не накладываться на оверлей; хода хватает в трее.
  Пузырь окончания показывается после скрытия оверлея, если он ещё
  актуален.

Основное окно открыто и в фокусе:

- системный пузырь не показывается;
- в шапке (`NavPanel`), рядом с кнопкой истории, стоит чип со спиннером и
  именем команды. По клику открывается поповер: что выполняется, сколько
  идёт и кнопка «Остановить» (обычная кнопка, не красная). После окончания
  чип на пару секунд показывает успех или ошибку со ссылкой «Открыть в
  истории» и исчезает;
- тосты для хода выполнения не используем: тосты внизу справа служат для
  сбоев, а чип стоит в шапке и с ними не спорит.

Переключение фокуса во время запуска переключает пузырь и чип на лету.

### Результат: в истории

Отдельной страницы и «последнего запуска» нет. Сейчас результат внешнего
запуска в историю не попадает: `saveOutput` вызывается, только когда текст
уходит из приложения, а у внешних запусков действия после запуска нет.
Поэтому:

- каждый внешний запуск, тихий или видимый, пишет запись в историю
  редактора: вход, результат или ошибку, команду и источник «Внешний
  запуск». Новое значение `EditorHistoryOrigin`. Задвоения с `saveOutput`
  нет, потому что внешние запуски его не вызывают. Внутренние запуски
  (хоткей, меню) сохраняются как сейчас;
- в `HISTORY_FILTERS` добавляется фильтр «Внешние запуски»;
- ошибки, отмены и таймауты попадают и в «Проблемы»;
- при выключенной истории запись не сохраняется: так настроил пользователь,
  а результат всё равно получает вызывающий;
- вход `--stdin` теперь тоже попадает в историю, которая может
  синхронизироваться через папку данных. Раньше документация предлагала
  `--stdin` для приватного ввода, теперь она прямо говорит, что вход
  сохраняется в истории, если та включена;
- технический журнал `actions.log` (`log_command_run`) остаётся как есть.

## Работы

Протокол и бэкенд:

- [ ] `API_VERSION` 5; `quiet` в запросе `run` (`activation-protocol`),

  флаг `--quiet` в `tyco-ctl`, поле в D-Bus `Run`. Старое приложение
  отвергает поле (`deny_unknown_fields`); `tyco-ctl` переводит это в
  понятную ошибку «нужен API 5».

- [ ] Валидация: `--quiet` несовместим с `--selection` и `--replace`.
- [ ] `ErrorCode::ConfirmationRequired`: стабильный код, D-Bus-имя ошибки,

  `ALL`, выход 3 (не временная ошибка, а разрешения команды).

- [ ] Отдельный код выхода для `Busy` (8) для всех запусков: сейчас `Busy`

  делит код 4 с «not found» и «disabled», и скрипт по коду выхода не
  отличит повод для повтора от постоянной ошибки.

- [ ] `ExternalJobs`: два слота, видимый и тихий; признак `quiet` у job.

  Тихий отказ `Busy` без `CommandRunRejected`.

- [ ] Проверка до старта: инструмент с `ask` в whitelist даёт

  `ConfirmationRequired`; `canRunQuietly` в `commands describe`.

- [ ] `job_execution::start`: при `quiet` не вызывать `visible_work`, не

  открывать `ActivationMode::CommandRun` и не показывать окно.

- [ ] `visible_work`: `EndVisibleWork` не отменяет тихий job.
- [ ] Где выполняется тихий job: скрытый quick webview отдельной сессией или

  основной webview, если он живёт при закрытом окне. Решить и описать,
  как он забирает job без активации (событие и `claim_external_job`),
  включая `commandRunTimeoutSec` и сбой job при перезагрузке webview.

- [ ] Событие о состоянии тихого запуска (старт, окончание, ошибка) для

  трея, пузыря, уведомления и чипа; `pnpm generate:desktop`.

- [ ] Трей: индикатор тихого запуска на обеих платформах.
- [ ] Linux: короткий пузырь старта без задержки и пузырь окончания; не

  показывать, пока в фокусе основное окно или оверлей. Windows:
  системное уведомление по окончании.

- [ ] Отмена тихого запуска из чипа через существующий `cancel_external_job`.

Фронтенд:

- [ ] Модель тихого запуска в `lib/commands/`: выполнение без оверлея и вне

  жизненного цикла оверлея и visibleWork, ошибки `InputRequired` и
  `ConfirmationRequired` вместо запросов; unit-тесты. Стор только
  связывает.

- [ ] Запись в историю для всех внешних запусков: новый origin, фильтр

  «Внешние запуски», попадание сбоев в «Проблемы»; тесты
  `history-filter`.

- [ ] Чип и поповер в `NavPanel`; тесты компонента над `loadFakeDesktop()`.
- [ ] Новый текст разрешения на внешний запуск в настройках команды.
- [ ] Ключи i18n во всех локалях (`pnpm check:i18n`).

Документация:

- [ ] `docs/external-control.md`: версия 5; `--quiet`, его несовместимости

  и ошибки; `canRunQuietly`; новый код выхода `Busy`; тихий запуск не
  завершает видимую работу и не мешает хоткеям; где видны ход и
  результат; что вход сохраняется в истории; убрать обещание, что каждый
  запуск показывается в оверлее.

- [ ] Примеры: основной — systemd user timer, cron — с оговоркой про

  `XDG_RUNTIME_DIR` и `DBUS_SESSION_BUS_ADDRESS`; повтор при `Busy` по
  коду выхода; что происходит, если Tyco не запущен.

- [ ] `docs/assistant-capabilities.md`, если затронуто.
- [ ] После выполнения перенести итог в `dev_docs/architecture.md` (два

  слота; тихий запуск не скрыт: индикатор в трее и запись в истории есть
  всегда; прервать видимую работу он не может, и она не прерывает его) и
  удалить этот план.

## Открытые вопросы

- Писать ли в историю внутренние запуски с хоткея и из меню, которые не
  дошли до `saveOutput`, чтобы история команд была полной. - пишем
- Трей есть не везде (GNOME без расширения). Можно ли это определить и  
  держать тогда пузырь «Выполняется» до конца запуска. - делаем там где возможно, без фанатизма
- Пузырь для Windows вместо уведомления, если понадобится паритет. - елси нельзя сделать пузырь значит используем уведомления

## Критерии готовности

- `pnpm validate:all` и `pnpm check:rust` без ошибок и предупреждений.
- `tyco-ctl run <id> --quiet --wait` из systemd timer не открывает окно и не
  меняет фокус. Пока он идёт, на обеих платформах виден индикатор в трее, а
  в основном окне чип. Результат или ошибка есть в истории.
- Тихий запуск во время диктовки идёт рядом, диктовка продолжается.
- Хоткей команды и `tyco-ctl open …` во время тихого запуска работают как
  обычно и тихий запуск не прерывают.
- Второй тихий запуск получает `Busy` с отдельным кодом выхода.
