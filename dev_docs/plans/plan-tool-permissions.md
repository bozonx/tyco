## 1. Позиционирование, идея и границы

**Что такое TyCo.** TyCo помогает работать с текстом и другими способами
ввода. Профили — это личные ассистенты: у каждого своя узкая специализация
(маркетолог, DevOps, бизнес-консультант, личный терапевт), своя память, своя
папка и проекты, которые подключил пользователь. С кодом профиль работать
может, но TyCo не код-агент, и инструменты под это не строятся.

Инструменты бывают встроенные, из плагинов и внешние (MCP). Права на все
них устроены одинаково: инструмент либо выключен, либо спрашивает, либо
всегда разрешён. Какие инструменты вообще доступны, зависит от того, где идёт
разговор: «Спросить у ИИ», ИИ-команда или чат профиля.

**Принципы:**

- **Нет доступа к компьютеру за пределами данных приложения.** Агент видит
  только `workspace/` своего профиля и проекты, подключённые к профилю.
  Внешнюю папку можно дать агенту единственным способом: подключить её к
  профилю как внешний проект (`AiProject.isExternal` + `targetPath`, уже
  есть). Путей, масок и «разрешённых папок» вне проектов нет и не будет. Так
  пользователь знает, что агент не тронет остальной компьютер.
  Команда пользователя (например, скрипт), которую пользователь сам отдал
  агенту, — его личное решение; отдельной обработки для неё нет.
- **Без computer use.** У агента нет инструментов для снимков экрана, чтения
  буфера обмена или выделения, управления окнами и вводом. Данные в агента
  передаёт только пользователь: вставкой, вложением, скриншотом, хоткеем.
  Вложения и скриншоты пользователя модель читает без вопросов.
- **Агент сам ничего не решает.** Агент использует только то, что пользователь
  включил и добавил. Ни один инструмент не меняет настройки, права, список
  инструментов, профили, проекты и команды. Результат инструмента (веб, MCP,
  файл) не может повысить права — это защита от prompt injection.
- **Три состояния вместо четырёх.** Для инструмента: выключен (модель его не
  видит), `ask`, `allow`. Отдельного `deny` для инструмента нет: запрещённый,
  но видимый модели инструмент только тратит контекст. `deny` остаётся
  внутри прав проекта (нет права чтения, записи или удаления).
- **Без турбо-режима.** Режима «ничего не спрашивать» нет ни глобально, ни на
  чат. Против усталости от вопросов: разумные значения по умолчанию (§ 3.3),
  одно подтверждение на пачку вызовов, «разрешить в этом чате» и «всегда
  разрешать» прямо из подтверждения.
- **Без UI `ask` = `deny`** (внешний API, ИИ-команда без окна), как сейчас.
- **Rust проверяет сам.** Webview описывает инструменты и спрашивает
  пользователя, но Rust на каждый вызов проверяет, что инструмент разрешён
  в этом контексте (как `ensure_web_enabled` и проверка корней файлов).
- **Без миграций.** Функция не выпущена (версия 0.1.0): старые поля
  `ProfileToolSettings.groups`, `AiCommandOperationConfig.allowedCommandIds`
  и `llm.webSearch.askAiAccess` заменяются, а не дополняются.

## 2. Источники инструментов

Источник — набор инструментов с общим названием, иконкой и переключателем.

| Вид        | Примеры                                                    | Откуда описание и риск                   |
| ---------- | ---------------------------------------------------------- | ---------------------------------------- |
| `core`     | файлы, веб, память, блоки ответов, позже код и изображения | код приложения                           |
| `plugin`   | инструменты, объявленные плагином                          | манифест плагина                         |
| `mcp`      | инструменты MCP-сервера                                    | подсказки MCP (только доверенный сервер) |
| `commands` | команды пользователя с описанием для ИИ                    | выбирает пользователь                    |

### 2.1. Риск инструмента

Каждый инструмент имеет `risk`:

- `read` — чтение и поиск без побочных эффектов (`read_file`, `web_search`);
- `write` — изменение данных пользователя (`write_file`, `edit_file`,
  `move_path`);
- `destructive` — удаление и необратимое (`delete_path`, MCP с
  `destructiveHint`);
- `external` — действие во внешнем мире (отправить письмо, создать событие;
  MCP с `openWorldHint` и без `readOnlyHint`).

Политика по умолчанию из риска: `read` → `allow`, остальное → `ask`.
Исключения и уточнения:

- память профиля и `workspace/` профиля — `allow` всегда (§ 3.3);
- команды пользователя — `ask`;
- **риск, объявленный извне, не снижает политику сам по себе.** Инструменты
  сторонних (не встроенных в сборку) плагинов — `ask` независимо от
  объявленного риска; объявленный риск только показывается. Подсказки MCP
  (`readOnlyHint` и др.) недоверенные по спецификации: они задают риск только
  у сервера, который пользователь пометил доверенным, иначе инструмент
  считается `external`. Пользователь может перевести любой из них в `allow`.

### 2.2. Инструменты плагинов

Новый вклад плагина `chatTools` в `packages/plugin-sdk`:

- поля: `id`, `labelKey`, `description` (для модели, на английском),
  `inputSchema`, `risk`, `run(input, context)`;
- имя для модели — `<plugin>__<tool>` через `tool-name.ts`, не пересекается с
  командами и MCP (тест);
- `run` получает `AbortSignal` и не получает доступа к файлам профиля: если
  нужен файл, модель передаёт текст аргументом или плагин работает через
  свои API SDK;
- провайдер `plugin` в `desktop-chat-tools.ts` собирает инструменты всех
  включённых плагинов.

Путь «операция плагина → команда → инструмент» остаётся для мест вне чата и
для пользовательских настроек операции (`operationConfig`).

## 3. Где какие инструменты доступны

### 3.1. «Спросить у ИИ» — веб и вспомогательное, без подтверждений

Чат для работы с текстом, уточнения фактов и быстрых ответов; он не трогает
данные пользователя. Рекомендуются быстрые модели (подсказка в выборе модели
и в `docs/`).

- веб (`web_search`, `web_fetch`) — один переключатель «Поиск в интернете» на
  странице настроек «Спросить у ИИ» (`SettingsChatTab.vue`), хранится рядом с
  `llm.tasks.chat`. Вместо `llm.webSearch.askAiAccess`;
- в настройках LLM остаётся только то, **как** искать (провайдер поиска,
  ключи) — общий сервис для «Спросить у ИИ», профилей и ИИ-команд;
- блоки ответов и собственные вложения (только чтение);
- после фазы 7 — песочница кода **без** монтирования файлов (чистые
  вычисления, сети нет).

**Подтверждений нет совсем:** личных данных в чате нет, кроме того, что
пользователь передал сам, поэтому канал «личные файлы → наружу» закрыт
границей. Нет: файлов профилей и проектов, памяти, команд, MCP, инструментов
плагинов. Это граница, а не настройка — переключателей для них в
«Спросить у ИИ» нет.

### 3.2. ИИ-команда — белый список, только `allow`

ИИ-команда часто работает без окна, поэтому `ask` в ней бессмыслен.
Пользователь сам настраивает команду, поэтому сам и добавляет в белый список
всё, что ей можно.

- `AiCommandOperationConfig.tools: ToolRef[]` вместо `allowedCommandIds` и
  `isToolsEnabled` (пустой список = без инструментов);
- в список можно добавить: команды, веб, инструменты плагинов, отдельные
  инструменты MCP-серверов — напрямую, без обёртки `core.mcp`;
- команда не вызывает саму себя, циклы (A → B → A) запрещены, глубина
  вложенных вызовов ограничена (константа, тест);
- нет файлов и памяти: у ИИ-команды нет профиля и проекта. Это граница, а не
  настройка;
- всё из списка выполняется как `allow`; при добавлении инструмента с риском
  `destructive` или `external` редактор показывает предупреждение;
- инструмент, выключенный глобально (сервер выключен, плагин удалён),
  пропадает из запуска, а редактор помечает его как недоступный.

### 3.3. Чат профиля — всё включено, лишнее выключают

Цель — чтобы ассистент не спрашивал по пустякам, но всё, что он может, было
видно и предсказуемо.

- **Память** — всегда `allow`, без настройки политики: это ядро профиля.
  Работает по `memoryMode` профиля, как сейчас. Изменения памяти видны в
  шагах ответа.
- **`workspace/` профиля** — полный доступ без вопросов, включая удаление.
- **Проекты** — право задаётся на связи «профиль ↔ проект»
  (`AiProfile.projectPermissions`, уже так): «Всегда разрешать» в одном
  профиле не меняет другой. Пресеты в UI раскрываются в
  `read` / `write` / `delete`:

  | Пресет          | `read`  | `write` | `delete` |
  | --------------- | ------- | ------- | -------- |
  | Только чтение   | `allow` | `deny`  | `deny`   |
  | Чтение и запись | `allow` | `ask`   | `ask`    |
  | Полный          | `allow` | `allow` | `ask`    |

  Плюс галочка «Удалять без вопроса» (`delete: 'allow'`), доступная только
  при `write: 'allow'`. Уровень `askAll` убирается.

- **Веб** — отдельные `web_search` (`allow`) и `web_fetch` (`allow` с
  правилом § 5) в источнике `core:web`, не зависят от переключателя
  «Спросить у ИИ».
- Остальные источники `core` и `plugin`, включённые глобально, приходят в
  профиль включёнными, с политикой по умолчанию (§ 2.1).
- Команды и MCP-серверы — явным выбором в профиле: их бывает много, и каждый
  инструмент занимает контекст. Рядом с выбором — примерный размер описаний
  инструментов в токенах.
- **Что агент может — видно в чате.** В шапке чата профиля короткая строка:
  «workspace · 2 проекта (чтение) · веб · 3 команды» с переходом в настройки
  профиля.

## 4. Уровни настройки: глобальный и профиль

Два уровня, третьего нет. Политика задаётся только в профиле — так ответ на
«где это настроено?» всегда один.

**Глобально (настройки → «Инструменты»): каталог.**

- Список источников: встроенные, плагины, MCP-серверы (добавление и
  настройка серверов — фаза 5 `plan-chat-tools.md`; там же отметка
  «доверенный сервер»).
- Переключатель источника: выключенный глобально источник недоступен нигде.
- Риск и политика по умолчанию каждого инструмента — только для просмотра.

**Профиль: выбор и политика.**

- Галочки на источниках и отдельных инструментах.
- Политика инструмента (`ask` ↔ `allow`), если она отличается от значения
  по умолчанию. Хранятся только отличия.

**Итог:** инструмент работает, если он включён глобально и в профиле;
политика — из профиля, иначе по умолчанию (§ 2.1). Для файлов итог
дополнительно ограничен правом проекта (чтение / запись / удаление).

### 4.1. Типы (`packages/shared`, Rust `models/user_config.rs`)

```ts
type ToolPolicy = 'ask' | 'allow'
type ToolRisk = 'read' | 'write' | 'destructive' | 'external'

/** Стабильная ссылка на источник или инструмент */
interface ToolRef {
  sourceKind: 'core' | 'plugin' | 'mcp' | 'commands'
  sourceId: string // 'files', '<pluginId>', '<serverId>', 'commands'
  toolName?: string // нет — весь источник
}

/** Глобально: `tools` в пользовательском конфиге */
interface ToolCatalogSettings {
  sources: Record<string, { isEnabled: boolean }> // ключ — `<kind>:<id>`
}

/** В профиле: заменяет нынешний `ProfileToolSettings.groups` */
interface ProfileToolSettings {
  sources: Record<string, { isEnabled: boolean }>
  disabledTools: string[]
  policies: Record<string, ToolPolicy> // ключ — `<kind>:<id>:<tool>`
  commandIds: string[]
  mcpServerIds: string[]
}

interface ProjectPermission {
  read: ProjectAccessMode
  write: ProjectAccessMode
  delete: ProjectAccessMode
}
```

Точные имена уточняются при реализации; ключи источников и инструментов
собирает одна функция в `lib/chat-tools/` и её зеркало в Rust.

## 5. Подтверждение вызова

`ChatToolApproval.vue` получает три ответа плюс отказ:

- «Разрешить один раз»;
- «Разрешить в этом чате» — до закрытия чата, по `approvalScope`
  (инструмент + проект / хост / сервер), как сейчас;
- «Всегда разрешать» — записывает `allow` в `policies` профиля (для файлов —
  повышает право проекта на эту операцию в этом профиле); показывается
  только в чате профиля;
- «Отклонить».

В подтверждении видно источник (встроенный / плагин / MCP-сервер) и риск.

**Пачка вызовов.** Если модель за один шаг просит несколько вызовов, которым
нужно подтверждение, пользователь видит одно подтверждение со списком
(«Разрешить все 5») и может раскрыть и отклонить отдельные.

**Защита от утечки.** После того как в чате прочитаны файлы проекта, любой
`external`-инструмент и `web_fetch` на URL, которого не было в разговоре и в
результатах поиска, спрашивает даже при `allow` — один раз на хост (сервер,
команду) в этом чате. Это закрывает сочетание «личные файлы + недоверенный
текст + канал наружу», не превращаясь в вопрос на каждый вызов. Принятый
остаточный риск: данные в тексте поискового запроса `web_search`.

## 8. Критерии готовности

- `pnpm validate:all` без ошибок и предупреждений.
- Unit-тесты на `tool-catalog.ts`, политику и проверку в Rust.
- Ни одного пути вне `workspace/` профиля и подключённых проектов (тест на
  корни и symlink остаётся зелёным).
- Нет инструментов для экрана, буфера обмена, выделения и окон; ни один
  инструмент не меняет настройки и права.
- Все новые ключи i18n во всех локалях, без неиспользуемых.
- Ручная проверка: «Спросить у ИИ» не видит файлов и команд и ничего не
  спрашивает; ИИ-команда вызывает только свой список; память и `workspace/`
  профиля работают без вопросов; пачка вызовов подтверждается одним
  диалогом; «Всегда разрешать» сохраняется в профиль и не влияет на другие
