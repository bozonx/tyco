## 1. Концепция и границы

Профили ИИ — консультанты по темам и помощники для рутинных действий: читают и
правят файлы проекта, ищут в интернете, вызывают пользовательские команды и
MCP-серверы, генерируют изображения и выполняют код для вычислений.

**Не делаем:** автономных агентов и фоновых задач (каждый цикл начинается с
сообщения пользователя и ограничен числом шагов); планировщика внутри
приложения; агента разработки с произвольным shell (код — только в песочнице);
computer use (отложен).

**Принципы:**

- Всё, что меняет данные или выходит наружу, проходит политику
  `allow` / `ask` / `deny` (`ProjectPermission` и доступ группы). По умолчанию
  `web` и `commands` — `ask`.
- Инструменты исполняются в Rust; webview описывает их модели и показывает
  вызовы. Исключение — песочница кода (Web Worker с WASM).
- Офлайн и CSP соблюдаются: сеть только через `services/net`, ключи в
  `services/secrets`, WASM-рантаймы упаковываются в приложение.
- Без UI (внешний API) `ask` работает как `deny`.
- Чат и быстрый запрос работают только на моделях с `canUseTools`; иначе
  `llmErrors.toolsRequired` сразу при выборе, модель не подменяется.
- Обрезка результата одна — при исполнении; в сообщении хранится ровно то, что
  видела модель.

## 2. Что сделано (фазы 1–4)

**Основа (фаза 1)**

- ai-kit 0.6.3: `toolApproval`, `activeTools` / `prepareStep`,
  `responseMessages` и `step-finish` в потоке, части `file`, `generateImage`,
  реэкспорт `jsonSchema` / `dynamicTool`, ошибка `tools_unsupported`.
- `LlmModel.canUseTools` (облачные — `true`, `openai-compatible` — `false`),

- `ChatMessage.parts` (`text`, `tool-call`, `tool-result`, `file`, `sources`;
  `reasoning` зарезервирован), Rust хранит части как JSON с полем `type`;
  `content` остаётся итоговым текстом. Экспорт выводит вызовы кратким блоком.
- `llm-client.stream()` с доменными событиями, ошибки `tools_unsupported` и
  `step_limit`.
- `lib/chat-tools/`: реестр провайдеров (`chat-tool-registry.ts`), политика и
  «разрешить в этой сессии» по ключу «инструмент + область»
  (`chat-tool-policy.ts`, `approvalScope`), нормализация вывода
  (`chat-tool-output.ts`), цикл (`chat-tool-loop.ts`), сессия
  (`chat-tools-session.ts`), сборка для десктопа (`desktop-chat-tools.ts`).
- Бюджет контекста учитывает части; старые результаты сжимаются первыми;
  `toolOutputBudgetCharacters` делится между вызовами хода (не меньше 2 000).
- `AiProfile.tools`: группы, доступ, лимит шагов (8). UI: `ChatToolCall.vue`,
  `ChatToolApproval.vue`, `ChatToolChange.vue` (diff), «Стоп» через `AbortSignal`.
- Отладочный `get_current_time` при `VITE_DEBUG_CHAT_TOOLS=true`.
- `propose_replies` (группа `replyBlocks`, всегда `allow`, во всех чатах).
- Память профиля — `memory-tools.ts` (`design-profile-memory.md`).

**Файлы (фаза 2)** — `services/ai_tools/files.rs`, `file_search.rs`,
`commands/ai_files.rs`; `file-tools.ts`: `list_files`, `read_file`
(PDF/DOCX через `chat-pdf.ts` / `chat-docx.ts`), `search_files`, `write_file`,
`edit_file`, `move_path`, `delete_path` (в корзину ОС). Корни `workspace/` и
`projects/<id>/`, защита от выхода за корень и symlink, служебные файлы скрыты.
Доступ группы — потолок над правами проекта. Вложения чата доступны как
`attachments/<name>` (`chat-files.md`). Список корней и прав вставляется в
системный промпт (`ChatToolProvider.instructions`). Флаг
`IS_AI_PROJECTS_ENABLED` снят.

**Команды (фаза 3)** — `command-tools.ts` через `registered-tool-adapter.ts`:
явный выбор `commandIds` в профиле, без описания для LLM команду не отдать,
`canRunFromChat` в `plugin-sdk`, отмена через `cancelScriptRun`.

**Интернет (фаза 4)** — `services/ai_tools/web.rs`, команда `run_ai_web_tool`,
`web-tools.ts`: `web_search` (`s.jina.ai`, `X-Respond-With: no-content`) и
`web_fetch` (`r.jina.ai`, Markdown). Ключ `web.jina` в `SecretStore`,
бесплатный тариф без ключа; `fetchMaxCharacters` (1 000–100 000, 15 000) и
ключ в `SettingsLlmTab.vue`; 429/401 отсылают в настройки LLM.

## 3. Осталось по фазам 1–4

### 3.1. Доработки по ревью ✅

- `web_fetch` режет страницу один раз: Rust отдаёт срез `offset` +
  `maxCharacters` и `totalCharacters`, webview оставляет 500 символов на
  заголовок и пометку «Characters a–b of n, call web_fetch with offset b».
- `web_fetch(url, offset?)` дочитывает длинные страницы.
- Отмена: `run_ai_web_tool` принимает `runId` (`web-<toolCallId>`),
  `cancel_ai_web_tool` прерывает запрос в Rust (`WebRuns`, `tokio::select!`).
  Тот же подход — для MCP.
- «Разрешить в этой сессии» для `web_fetch` действует на хост URL
  (`approvalScope`).
- Из поиска убран `X-No-Cache`; проверка HTML-ответа вынесена в `is_html_body`.

### 3.2. Ручная проверка (Linux X11 и Wayland)

- **Основа:** старые чаты открываются; чат без инструментов ведёт себя как
  раньше (индикатор набора у модели с рассуждениями); `get_current_time`
  вызывается на Gemini, DeepSeek и локальной модели через openai-compatible;
  подтверждение и «Стоп» работают; сохранённый чат с шагами продолжается (на
  Gemini 3 — прошлые вызовы принимаются без thought signatures).
- **Файлы:** чтение и поиск в `workspace/` и проекте с правом чтения; запись
  с `ask` показывает diff, сессионное разрешение действует только в своём
  проекте; `deny` блокирует всё; PDF-вложение читается как
  `attachments/<name>`; удаление — в корзину; symlink наружу не выпускает.
- **Команды:** команда без описания недоступна; после описания включается в
  `commandIds`; `ask` показывает аргументы; сессионное разрешение работает;
  «Стоп» отменяет скрипт; плагин с `canRunFromChat: false` не предлагается.
- **Интернет:** при выключенной группе инструментов нет; поиск возвращает
  сниппеты и ссылки; `web_fetch` укладывается в бюджет, длинная страница
  дочитывается по `offset`; при `ask` показывается URL, сессионное разрешение
  не действует на другой хост; «Стоп» прерывает запрос; 429 без ключа предлагает указать ключ.

## Фаза 5: MCP

### 5.1. Rust: `src-tauri/src/services/mcp/`

- Клиент на крейте `rmcp`. Транспорты: stdio (процесс, окружение, рабочая
  папка; запуск через `services/platform/` — PATH, `npx`/`uvx` на Windows) и
  Streamable HTTP через `services/net`.
- OAuth удалённых серверов: токены в `secrets`, вход через системный браузер
  с обратным вызовом на localhost или deep link.
- Жизненный цикл: ленивый запуск, остановка при простое и выходе, перезапуск
  после падения, stderr в диагностику. Кэш списка инструментов,
  `tools/list_changed`.
- IPC: `mcp_list_servers`, `mcp_list_tools`, `mcp_call_tool` (отмена →
  `notifications/cancelled`, по образцу `WebRuns`), статус сервера.
- Rust проверяет на каждый вызов, что сервер включён в профиле и не `deny`
  (как `ensure_web_enabled`).

### 5.2. Конфигурация

- Серверы в конфиге: `id`, название, транспорт, команда/URL, окружение
  (секреты — `tyco-secret:<id>`). Импорт JSON `mcpServers` (Claude Desktop /
  Cursor).
- В профиле — выбор серверов и отдельных инструментов; политика на сервер с
  переопределением на инструмент; `readOnlyHint` / `destructiveHint` задают
  политику по умолчанию (по умолчанию `ask`).

### 5.3. Frontend

- `ChatToolProvider` «mcp» в `desktop-chat-tools.ts`: `dynamicTool` с именами
  `<server>__<tool>` через `tool-name.ts` (ограничения провайдеров на имена),
  `approvalScope` — сервер.
- Результаты: текст и изображения (частью `file`, если модель их принимает).
  Ресурсы и промпты MCP — позже.
- i18n во всех локалях.

## Фаза 7: Выполнение кода в песочнице

Для вычислений и обработки файлов (таблицы, данные, графики), не для
разработки.

- Pyodide в Web Worker, упакованный в приложение; пакеты: stdlib, `numpy`,
  `pandas`, `matplotlib`, остальное — только локально. Опционально JS через
  `quickjs-emscripten`.
- `run_code(language, code)`: stdout/stderr, результат, созданные файлы;
  лимиты времени, памяти (перезапуск воркера) и вывода. Сети нет.
- В виртуальную ФС монтируется копия нужных файлов (`workspace/` и проекты с
  правом чтения); созданные файлы возвращаются через файловые инструменты фазы
  2 с теми же правами на запись.
- Проверить `experimental_sandbox` AI SDK 7. Замерить размер сборки; при
  необходимости рантайм скачивается по запросу и хранится локально.
