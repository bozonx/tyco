# План: режим «Диалог» (транскрипт созвона с живым переводом)

Статус: план утверждён, к реализации не приступали.
Дата: 2026-11-20
Зависимость: микширование и нормализация микрофона со звуком компьютера
(`src-tauri/src/services/voice/microphone_mix.rs`, `CaptureSource::MicrophoneAndSystemMix`).
Перед началом эта работа должна быть закоммичена отдельно.

## 1. Цель

Вкладка «Диалог» в основном окне слушает созвон в любом приложении (Zoom,
Google Meet, Microsoft Teams и т. п.) и показывает его как ленту реплик:
собеседник слева, пользователь справа. Реплики собеседника сразу переводятся.
Транскрипт с разметкой «кто говорит» можно скопировать или отправить в меню
действий (например, в трансформацию, чтобы сделать саммари).

## 2. Утверждённые решения

- **Вкладка основного окна, не отдельный оверлей.** Новый маршрут и пункт
  навигации «Диалог» рядом со «Спросить AI». Состояние сессии живёт в
  Pinia-сторе, а не во вьюхе: при переходе на другие вкладки диалог
  продолжается, лента сохраняется.
- **Долгая фоновая сессия.** В отличие от голосового ввода и «слушать»
  (которые живут, пока открыт их оверлей), диалог идёт, пока пользователь явно
  не нажмёт «Стоп» или не выйдет из приложения. Сворачивание, скрытие окна и
  смена вкладки его не останавливают. Лимита `MAX_RECORDING_MS` нет.
- **Источник — переключатель:**
  - «Микрофон + компьютер»: два канала, лента с баблами с обеих сторон;
  - «Только компьютер»: только собеседник, реплики рисуются абзацами без
    баблов (та же модель данных, другая отрисовка).
  - Отдельное приложение как источник пока не делаем.
- **Каналы не смешиваются.** Микрофон и звук компьютера — два отдельных
  потока и две STT-сессии. Сторона реплики («Я» / «Собеседник») определяется
  каналом, без диаризации.
- **Перевод каскадом:** STT → перевод финальных сегментов собеседника через
  `lib/translation` (машинный или LLM-провайдер). Свою речь не переводим.
  Перевод показывается внутри бабла собеседника. Переключатель отображения:
  «перевод» / «оригинал» / «оба» (по умолчанию «оба»: перевод крупно,
  оригинал мелко и приглушённо). Без языка перевода показывается только
  оригинал.
- **Свёрнутый вид = субтитры.** Кнопка «Свернуть» переводит основное окно в
  компактный режим: окно становится узкой полосой поверх всех окон, навигация
  и шапка скрыты, окно двигается и меняет ширину. Показывается только
  последняя реплика собеседника: перевод крупно, оригинал мелко под ним.
  «Развернуть» возвращает прежние размер, позицию и режим окна. Размер и
  позиция полосы запоминаются отдельно.
- **Приоритет у диалога.** Пока диалог активен, голосовой ввод, голосовые
  команды и «слушать» не захватывают звук: их хоткеи не запускают захват и
  показывают явное сообщение «Звук занят диалогом» (оверлей не открывается
  или открывается с этим сообщением, без записи). Диалог никогда не
  вытесняется другим захватом.
- **AI-саммари не делаем.** Есть только экспорт транскрипта (см. 3.2).

## 3. Этапы

### 3.1. Rust: двухканальный захват и приоритет

Файлы: `src-tauri/src/services/voice.rs`, `voice/source.rs`,
`voice/session.rs`, `voice/microphone_mix.rs`, `voice/mixer.rs`,
`src-tauri/src/commands/voice.rs`.

- Новый вариант источника, например
  `CaptureSource::Dialog { is_microphone_enabled: bool }` (точное имя и
  форму выбрать по месту). Без микрофона это захват всего звука компьютера в
  один канал.
- С микрофоном: один сеанс, два канала, звук отправляется по существующему
  аудиоканалу как **стерео PCM16 с чередованием** (ch0 — микрофон, ch1 —
  компьютер). `VoiceCaptureInfo` сообщает число каналов. Выравнивание по
  времени — через `StreamMixer`-подобную логику без суммирования, громкость —
  `LoudnessNormalizer` на каждый канал отдельно. Общий код с
  `microphone_mix.rs` вынести, не дублировать.
- **Подавление эха v1:** гейтинг канала микрофона. Пока в канале компьютера
  идёт речь, а микрофон заметно тише и повторяет его по огибающей, сегмент
  микрофона заглушается. Настоящий AEC (WebRTC AEC3) — позже.
- **Приоритет:** сеанс захвата помечается как диалоговый. Сейчас
  `start_capture_with` вызывает `supersede_capture_unlocked` — новый захват
  вытесняет старый. Для диалогового сеанса этого делать нельзя: попытка
  запустить другой захват возвращает отдельную ошибку (например
  `AppError::Busy` / новый вариант с понятным кодом), по которой фронтенд
  показывает «Звук занят диалогом». Запуск диалога при уже идущей диктовке —
  вытесняет её, как сейчас.
- Без лимита длительности для диалогового сеанса; уровни звука — по каждому
  каналу.
- Юнит-тесты: чередование и выравнивание каналов, гейтинг эха, отказ
  вытеснять диалог, вытеснение диктовки диалогом.
- `pnpm generate:desktop` после изменения команд и типов.

### 3.2. Модель `apps/desktop-ui/src/lib/dialog/`

Модели без импорта сторов, компонентов и `@tauri-apps/*`; зависимости
инжектируются; на каждый модуль — юнит-тесты.

- `dialog-transcript.ts` — сегменты
  `{ id, side: 'me' | 'remote', startMs, endMs, text, isFinal, translation?, translationState }`
  и склейка в реплики: новая реплика начинается, когда заговорила другая
  сторона или после паузы больше ~1,5 с. Перебивания: обе реплики открыты,
  порядок по времени начала.
- `dialog-session.ts` — жизненный цикл: старт и стоп захвата, демультиплексирование
  стерео в два потока, две STT-сессии через существующие `stt-client` /
  `rotating-stt-stream` (у провайдеров есть лимиты длительности сессии),
  переподключение при сбоях без потери ленты, статусы каналов.
- `dialog-translation.ts` — очередь перевода финальных сегментов собеседника:
  порядок сохраняется, в контекст LLM передаются последние N сегментов, при
  ошибке сегмент помечается, а оригинал остаётся. Опциональный черновой
  перевод interim-хвоста — не в v1.
- `dialog-export.ts` — транскрипт в текст с блоками по репликам:

  ```
  [00:03] Собеседник: Can we move the release to next week?
          Перевод: Мы можем сдвинуть релиз на следующую неделю?
  [00:09] Я: Да, если успеем с тестами
  ```

  Включать ли перевод — параметр. Подписи сторон — через i18n.

### 3.3. UI: вкладка и компактный режим

- Тонкий стор `stores/dialog.ts`, который связывает модель с IPC, STT и
  переводом.
- Маршрут и пункт навигации (`lib/navigation`), вьюха `views/DialogView.vue`.
- Компоненты в `components/dialog/`:
  - `DialogToolbar` — переключатель источника, язык перевода, режим
    отображения (перевод / оригинал / оба), «Копировать», «В меню действий»,
    «Свернуть», старт и стоп, индикаторы уровня каналов;
  - `DialogFeed` — лента с автопрокруткой, которая останавливается, когда
    пользователь прокрутил вверх;
  - `DialogTurn` — бабл (режим с микрофоном) или абзац (только компьютер);
    interim-текст приглушён;
  - `DialogSubtitles` — компактный вид.
- Компактный режим окна: команда в Rust (resize, always-on-top, запоминание и
  восстановление геометрии); логика окна — в `services`, команда остаётся
  адаптером. Проверить, что скрытое или минимизированное окно не тормозит
  поток распознавания на Linux и Windows.
- Блокировка остальных голосовых режимов: по ошибке «занято диалогом» из
  3.1 голосовой ввод, голосовые команды и «слушать» показывают сообщение
  вместо записи.
- «В меню действий» передаёт экспортированный транскрипт как текст в меню
  действий (как выделенный текст), где доступна трансформация.

### 3.4. Настройки, i18n, документация

- Секция конфига `dialog` в `packages/shared/src/user-config/`:
  `source` (`microphoneAndSystem` | `system`), `translationTargetLanguage`
  (пусто — без перевода), `textDisplay` (`translation` | `original` | `both`),
  провайдер перевода (по умолчанию — общие настройки перевода), геометрия
  компактного режима. Обновить `user-config-schema.json`; изменения — через
  `updateUserConfig(patch)`; вкладка настроек — через
  `createSettingsSession` (`dev_docs/ui-system.md`). Учесть
  `dev_docs/config-storage.md`.
- Ключи i18n во всех локалях с настоящими переводами, `pnpm check:i18n`.
- По окончании: итог перенести в `dev_docs` (раздел о голосе/диалоге), в
  `docs/` — короткое описание для пользователя; этот план удалить.

## 4. Не делаем сейчас (позже)

- Отдельное приложение как источник диалога.
- AEC3 вместо гейтинга.
- Диаризация нескольких собеседников (Deepgram `diarize` / `multichannel`).
- Диктовка во время диалога (временная передача микрофона).
- Перевод своей речи, черновой перевод interim-текста.
- Режим Gemini Live с произвольными инструкциями вместо каскада.
- Специальное AI-саммари и сохранение аудио.

- `pnpm check`, `pnpm test`, `pnpm check:rust`, `pnpm test:rust`.
- Ручная проверка через `pnpm tauri:dev`: созвон с наушниками и без,
  оба источника, сворачивание в субтитры и обратно, свёрнутое и скрытое окно,
  попытка запустить голосовой ввод и «слушать» во время диалога, долгая сессия
  (дольше лимита сессии STT-провайдера).
