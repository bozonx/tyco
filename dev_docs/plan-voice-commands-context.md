# План: выделенный текст как контекст голосовых команд

Статус: реализован.
Обновлено: 2026-11-04.

Дополняет [design-voice-commands.md](design-voice-commands.md).

## Решение

- Хвост после фразы вызова всегда остаётся основным текстом команды. Resolver,
  разбор хвоста и проверки входа не меняются.
- Выделение — необязательный дополнительный контекст. Команда сама решает,
  использовать ли его: плагин читает `ToolCall.context`, скрипт или вебхук
  подставляет `{{SELECTION}}`, остальные его игнорируют.
- Захватывать ли выделение, решает точка вызова, а не команда: выделение
  копируется из целевого окна до открытия оверлея, когда команда ещё не
  произнесена. Для этого используется существующий `actionPages[].inputMode`:
  кнопка голосовых команд на странице `selection` передаёт выделение, на
  странице `none` — нет. Новой настройки и отдельного режима активации нет.
- Отдельный хоткей `voiceCommands` по-прежнему открывает оверлей без контекста.
- Нераспознанная фраза никуда не передаётся: пользователь видит транскрипт и
  повторяет команду.
- `voiceTransformation` остаётся без изменений.
- Выделение не добавляется в prompt LLM pre-transform: поведение существующих
  команд не меняется.

## Этапы

1. **Контракты.** `context?: { selectionText: string }` в `InvocationOptions`
   и `ToolCall` (plugin-sdk). Плейсхолдер `{{SELECTION}}` для скриптов и
   вебхуков, синхронно в TS и `command_library.rs`. `voiceCommands` в
   `STANDARD_ACTION_IDS`.
2. **Rust.** Проверить, что выделение страницы доходит до оверлея голосовых
   команд, открытого из меню; прямой хоткей `VoiceCommands` выделение не берёт.
3. **Модель.** `createVoiceCommandModel` получает `context`, передаёт его в
   `run`. Команда с `{{SELECTION}}` без контекста — ошибка проверки, а не
   запуск с пустой строкой.
4. **Исполнение.** Проброс `context` в `ToolCall` и подстановку `{{SELECTION}}`.
5. **UI.** Тот же `VoiceCommandsView`; при наличии контекста сверху
   `TextPreview` выделения. Пункт `voiceCommands` в меню действий и
   настройках страниц, i18n. Пустое выделение на странице `selection` не
   блокирует голосовые команды.
6. **Документация.** Обновить §7 `design-voice-commands.md`,
   `docs/external-control.md` (`{{SELECTION}}`).

Проверка: `pnpm check`, `pnpm test`, `pnpm check:rust`, `pnpm test:rust`;
после изменений контрактов — `pnpm generate:desktop`.
