# План реализации проверки орфографии (Hunspell) — полный цикл

Статус: черновик плана, к реализации не приступали.
Дата: 2026-09-20
Зависимость: `dev_docs/plan-cm6-migration.md`, этапы 1–4 (нужны CM6 и контекстное меню).

## 1. Требования

- Собственный спеллчек на словарях Hunspell (`.aff` + `.dic`), а не системный `spellcheck` браузера.
- Слова с ошибками подчёркиваются красной волной.
- По ПКМ на слове — меню с вариантами исправления, «Добавить в словарь», «Пропустить слово».
- Словари скачиваются по требованию и кешируются локально.
- Работа без интернета после скачивания словаря.
- Проверка не должна тормозить ввод.

## 2. Архитектурные решения

**Нативный спеллчек выключаем.** В CM6 ставим `EditorView.contentAttributes.of({ spellcheck: 'false', autocorrect: 'off', autocapitalize: 'off' })` — иначе получим две волны и два конфликтующих контекстных меню.

**Движок — в Web Worker.** Hunspell на больших словарях (русский `.dic` — сотни тысяч форм) блокирует поток при загрузке и при пакетной проверке. В проекте уже есть `ui/src/workers/llm.worker.ts` и `whisper.worker.ts` — тот же паттерн.

**Выбор библиотеки: `hunspell-asm` (WASM-сборка настоящего Hunspell).**
Альтернатива `nspell` — чистый JS, проще, но реализует подмножество формата `.aff` и на русской и немецкой морфологии даёт заметно больше ложных срабатываний. Для приложения, где подсветка ошибок — заявленная функция, берём настоящий Hunspell. Цена: ~500 КБ WASM (грузится лениво, только когда спеллчек включён) и работа с виртуальной ФС WASM-модуля.

**Словари скачивает Rust, а не фронтенд.** Причины: CSP в Tauri (см. `tauri:dev` в корневом `package.json`), потребность писать в кеш-директорию приложения, и уже существующий в проекте паттерн скачивания моделей (`src-tauri/src/commands/llm.rs`, `whisper.rs`, `src-tauri/src/services/storage.rs`).

**Проверяем только видимую область.** Держать результат для всего документа не нужно: декорации CM6 запрашиваются для видимого диапазона. Это делает стоимость проверки независимой от размера буфера.

**Пользовательский словарь — на стороне приложения, не Hunspell.** Отдельный список слов в конфиге пользователя, который при инициализации подгружается в движок и проверяется первым.

## 3. Схема данных

### Файлы на диске

```
<app_cache_dir>/dictionaries/
  ru_RU/
    ru_RU.aff
    ru_RU.dic
    metadata.json     { language, files: [{name, size, sha256}], complete: bool, source_url }
  en_US/
    ...
```

Кеш-директория, а не data: словарь всегда можно перекачать. Берём `app_cache_dir` из
`src-tauri/src/services/storage.rs` и добавляем `app_dictionaries_dir(app)` рядом с
`app_llm_models_dir` / `app_whisper_models_dir`.

### Пользовательский словарь и игнор-лист

В `packages/shared/src/user-config.ts`:

```ts
spellcheck: {
  enabled: boolean            // по умолчанию true
  language: string | 'auto'   // коды из ui/src/lib/locale/language.ts, напр. 'ru_RU'
  userWords: string[]         // «Добавить в словарь» — постоянно
}
```

Игнор-лист сессии («Пропустить слово») в конфиг не пишется — живёт в Pinia-сторе и умирает вместе
с окном.

### Источник словарей

Основной источник — репозиторий LibreOffice dictionaries (лицензии LGPL/MPL/GPL, совместимы с
раздачей вместе с приложением). Конкретные URL закрепить константами в Rust рядом со списками
файлов моделей в `llm.rs`, чтобы не тянуть индекс из сети. Маппинг «код языка → путь словаря»
держать в `packages/shared`, чтобы его видели и фронт, и настройки.

Языки первой очереди: `ru_RU`, `en_US`, `en_GB`, `de_DE`, `fr_FR`, `es_ES`, `uk_UA`.
Остальные из `SUPPORTED_USER_LANGUAGE_OPTIONS` — по мере необходимости; для языков без словаря
спеллчек просто выключается, без ошибки.

## 4. Этапы

### Этап 1. Бэкенд: скачивание и хранение словарей

Файл: `src-tauri/src/commands/dictionary.rs`, регистрация в `src-tauri/src/main.rs`.

Команды (по образцу `commands/llm.rs`):

- `is_dictionary_downloaded(language) -> bool` — `metadata.complete` + проверка наличия и размеров файлов;
- `get_dictionary_metadata(language) -> Option<DictionaryMetadata>`;
- `download_dictionary(language)` — качает `.aff` и `.dic`, пишет во временные файлы, затем
  атомарно переименовывает, в конце пишет `metadata.json` с `complete: true`;
  прогресс отдаёт событием `dictionary://download-progress`;
- `read_dictionary(language) -> DictionaryPayload` — отдаёт содержимое обоих файлов во фронт
  (`.aff` как строка, `.dic` как `Vec<u8>`, чтобы не ломать кодировку);
- `delete_dictionary(language)`;
- `list_available_dictionaries() -> Vec<DictionaryInfo>` — из статической таблицы, с флагом
  «скачан / не скачан».

Важные детали:

- незавершённое скачивание не должно выглядеть завершённым — отсюда схема «temp → rename → metadata»;
- размер русского словаря — порядка 5–10 МБ в распакованном виде, чанкование как у LLM-моделей
  не требуется, но прогресс показывать нужно;
- `get_storage_info` в `storage.rs` дополнить размером директории словарей, чтобы они были видны
  в настройках хранилища.

Тесты: unit на разбор/запись `metadata.json` и на определение «скачан ли словарь» при частично
удалённых файлах.

### Этап 2. Воркер со спеллчекером

Файл: `ui/src/workers/spellcheck.worker.ts`.

Протокол сообщений:

```
→ init      { affText, dicBytes, userWords }
← ready     { language }
→ check     { requestId, words: string[] }
← checked   { requestId, misspelled: number[] }   // индексы слов из запроса
→ suggest   { requestId, word }
← suggested { requestId, suggestions: string[] }
→ addWord   { word }
→ dispose
← error     { message }
```

Реализация:

1. Лениво импортировать `hunspell-asm` — только по первому `init`, чтобы WASM не попадал в
   стартовый бандл.
2. Смонтировать `.aff` / `.dic` в виртуальную ФС модуля и создать инстанс Hunspell.
3. Внутри воркера держать `Map<string, boolean>` — кеш вердиктов по словам. В типичном тексте
   слова повторяются, а вызов в WASM не бесплатный. Кеш сбрасывать при смене языка и при
   добавлении слова в пользовательский словарь.
4. Пользовательские слова проверять до обращения к Hunspell.
5. `suggest` вызывать **только** по запросу из контекстного меню, никогда пакетно — это самая
   дорогая операция Hunspell.

Тесты (vitest, без реального WASM — через мок движка): протокол, кеш, приоритет пользовательского
словаря, сброс кеша.

### Этап 3. Клиент воркера и стор

Файлы: `ui/src/lib/editor/spellcheck/client.ts`, `ui/src/stores/spellcheck.ts`.

Стор отвечает за жизненный цикл:

- `status: 'off' | 'no-dictionary' | 'downloading' | 'loading' | 'ready' | 'error'`;
- текущий язык (с разрешением `auto` → язык из конфига пользователя);
- `userWords` (синхронизируется с конфигом через существующий механизм сохранения конфига);
- `sessionIgnored: Set<string>`;
- действия: `enable()`, `disable()`, `setLanguage()`, `downloadCurrent()`, `addWord(word)`,
  `ignoreWord(word)`.

Клиент — тонкая обёртка над воркером с промисами по `requestId` и таймаутом на ответ.
Если воркер упал — статус `error`, редактор продолжает работать без подсветки (спеллчек никогда
не должен ломать ввод).

### Этап 4. Токенизация

Файл: `ui/src/lib/editor/spellcheck/tokenize.ts`.

Правила:

- слово = последовательность букв по `\p{L}` плюс внутренние `'` и `-` (`Unicode`-флаг обязателен);
- отбрасываем: токены с цифрами, токены целиком в верхнем регистре (аббревиатуры), токены короче
  3 символов, URL и e-mail, слова с `_` (идентификаторы кода), `@упоминания` и `#хештеги`;
- дефисные слова проверяем целиком, и если целиком неизвестно — по частям (иначе на русском будет
  много ложных срабатываний);
- ё/е: полагаемся на словарь, своих нормализаций не делаем.

В Markdown-режиме дополнительно исключаем по `syntaxTree` из `@codemirror/language` узлы:
`InlineCode`, `FencedCode`, `CodeBlock`, `URL`, `LinkTarget`, `HTMLBlock`, `HTMLTag`.
Без этого вставленный код даст сплошную красную волну — это главный источник шума.

Тесты: покрыть таблицей кейсов (русский, английский, смешанный текст, код, ссылки, дефисы,
апострофы, эмодзи).

### Этап 5. Расширение CM6 и подсветка

Файл: `ui/src/lib/editor/spellcheck/extension.ts`.

1. `StateField<DecorationSet>` хранит текущие декорации; при правках документа они
   переносятся через `decorations.map(tr.changes)`, чтобы подсветка не «прыгала» во время набора.
2. `ViewPlugin` следит за `update.docChanged` и `update.viewportChanged`; с дебаунсом ~300 мс
   берёт текст видимого диапазона (с небольшим запасом по строке в обе стороны), токенизирует,
   шлёт `check` в воркер.
3. Ответ воркера применяется `StateEffect`'ом `setSpellErrors` → пересчёт `DecorationSet`.
   Ответы с устаревшим `requestId` игнорируются.
4. Декорация: `Decoration.mark({ class: 'tyco-spell-error' })`.
5. Слово, внутри которого сейчас стоит курсор, **не подчёркиваем** — иначе волна мигает под
   каждым недопечатанным словом. Подсвечиваем его после ухода курсора.
6. Стиль волны — CSS в `ui/src/assets/main.css`:

```css
.tyco-spell-error {
  text-decoration: underline wavy var(--color-error);
  text-decoration-skip-ink: none;
  text-underline-offset: 3px;
}
```

`text-decoration: wavy` поддерживается в WebKitGTK и WKWebView (целевые webview Tauri), поэтому
SVG-фон не требуется.

Критерий приёмки: набор текста на 50 000 знаков не даёт заметных лагов; переключение вкладок/скролл
подсвечивают новую область без мигания уже проверенного.

### Этап 6. Интеграция с контекстным меню

Доработка `EditorContextMenu.vue` из этапа 4 плана CM6.

По ПКМ:

1. `view.posAtCoords({ x, y })` → позиция;
2. проверяем, попадает ли позиция в диапазон декорации `tyco-spell-error`;
3. если да — асинхронно запрашиваем `suggest` у воркера и показываем меню сразу, с состоянием
   «загрузка» в блоке вариантов (Hunspell на suggest может думать десятки миллисекунд);
4. пункты меню:
   - до 5 вариантов исправления (клик → транзакция замены диапазона слова, `userEvent: 'tyco.spell'`,
     то есть отдельный шаг undo);
   - «Добавить в словарь» → `spellcheckStore.addWord` → сброс кеша → перепроверка видимой области;
   - «Пропустить» → в `sessionIgnored` → перепроверка;
   - разделитель, затем стандартные Вырезать / Копировать / Вставить / Вставить как текст.
5. Если слово не ошибочное — блок вариантов не показываем, остаются только команды буфера обмена.

Все подписи — через i18n, ключи `editor.spell.*`.

### Этап 7. Настройки и UI состояния

В `ui/src/components/Settings.vue` (рендерится через `FieldsByCfg`) добавить секцию «Орфография»:

- переключатель «Проверять орфографию»;
- выбор языка словаря (`auto` + скачанные + доступные для скачивания);
- кнопка «Скачать словарь» с прогрессом (подписка на `dictionary://download-progress`);
- размер словаря и кнопка «Удалить»;
- список пользовательских слов с возможностью удалить слово.

В редакторе — ненавязчивый индикатор статуса: если язык выбран, а словарь не скачан, показываем
одноразовое предложение скачать (через `useToast`), а не молчим.

### Этап 8. Приёмка и тесты

Автотесты:

- `tokenize` — табличные кейсы;
- воркер-протокол на моке движка;
- расширение CM6: правка документа сдвигает декорации корректно (проверяется на `EditorState`
  без DOM);
- Rust: метаданные словаря, определение завершённости скачивания.

Ручной прогон:

1. Чистая установка → спеллчек включён, словаря нет → предложение скачать → скачивание с прогрессом
   → подсветка появилась без перезапуска.
2. Обрыв сети посередине скачивания → повторный запуск скачивает заново, битого состояния нет.
3. Русский текст с ошибками, английский текст с ошибками, смешанный текст.
4. Вставка кода (fenced и просто отступом) → волны нет.
5. Вставка текста со ссылками и e-mail → волны нет.
6. «Добавить в словарь» → слово перестаёт подсвечиваться во всём документе и после перезапуска.
7. «Пропустить» → перестаёт подсвечиваться до перезапуска.
8. Исправление через меню → Ctrl+Z возвращает исходное слово одним шагом.
9. Документ на 100 000 знаков → ввод остаётся плавным.
10. Работа в офлайне после скачивания словаря.

## 5. Риски

| Риск                                    | Смягчение                                                                                                     |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Ложные срабатывания на коде и ссылках   | Исключение узлов по `syntaxTree` + правила токенизации (этап 4)                                               |
| Долгая первая загрузка словаря в память | Загрузка в воркере, статус `loading` в UI, редактор работает без подсветки                                    |
| Размер WASM в бандле                    | Динамический импорт `hunspell-asm` только при включённом спеллчеке                                            |
| Мигание волны при наборе                | Не подсвечиваем слово под курсором (этап 5, п.5)                                                              |
| Лицензии словарей                       | Только LibreOffice dictionaries; лицензию каждого словаря сохранять рядом с файлами и показывать в настройках |
| Слабое качество `suggest` для русского  | Опционально (отдельная задача): дополнять варианты подсказкой от локальной LLM, которая в проекте уже есть    |

## 6. Вне области этого плана

- Проверка грамматики и пунктуации (это задача AI-действий, а не Hunspell).
- Спеллчек в `ChatInput.vue` и `WriteModeInput.vue` — они остаются на `FieldTextArea`;
  расширение написано так, чтобы его можно было подключить к ним позже без переделки.
- Автозамена при наборе.
