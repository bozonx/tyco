# Tauri Quick Lab

Изолированная лаборатория: доказать или опровергнуть, что на Tauri панель
быстрого ввода по хоткею успевает принять **первый же символ**. Не входит
в сборку основного приложения, свой крейт со своим workspace.

Меряется **потеря символов**, а не задержка. Задержка сама по себе ничего не
доказывает: важно, сколько из набранного доехало до поля. Символы, не дошедшие
до панели, не исчезли — они ушли в то окно, которое было в фокусе до вызова.

## Критерий приёмки

**20 из 20 попыток: панель появляется внизу экрана, полупрозрачная, и все 8
символов зонда оказываются в поле.** Меньше 20/20 — стратегия не принята.

## Три оси, восемь комбинаций

Стратегия задаётся переменными окружения, по одной на ось:

| Переменная      | Значения                      | Что проверяет                                                           |
| --------------- | ----------------------------- | ----------------------------------------------------------------------- |
| `LAB_WINDOW`    | `toplevel` (умолч.) / `layer` | обычное окно против `zwlr_layer_shell_v1` с прижатием к низу            |
| `LAB_LIFECYCLE` | `hideshow` (умолч.) / `keep`  | уничтожать поверхность при скрытии или держать замапленной              |
| `LAB_DOM`       | `warm` (умолч.) / `cold`      | поле смонтировано и сфокусировано всегда против монтирования при показе |

`cold` воспроизводит сегодняшнее поведение TyCo, где роутер монтирует
`EditorInput` заново на каждый показ. `warm` — предлагаемое исправление.
Сравнение этих двух при прочих равных и есть главный замер.

`toplevel` на Wayland не умеет себя позиционировать: окно выйдет по центру.
Это не баг лаборатории, а ровно та причина, по которой нужен `layer`.

## Сборка

Вариант с layer-shell требует системной библиотеки:

```sh
sudo pacman -S gtk-layer-shell
```

```sh
cargo build --features layer          # с layer-shell
cargo build                           # только toplevel, без системной зависимости
```

## Запуск

```sh
LAB_WINDOW=layer LAB_DOM=warm LAB_METRICS=/tmp/lab-layer-warm.csv \
  ./target/debug/tauri-quick-lab
```

Окно стартует скрытым. Управление — Unix-сокет в `$XDG_RUNTIME_DIR`:

```sh
socat - UNIX-CONNECT:$XDG_RUNTIME_DIR/tauri-quick-lab.sock
# show 1 <unix-nanos> | hide | result 1 8 | ping | quit
```

`LAB_SOCKET_SUFFIX` разводит параллельные экземпляры по разным сокетам.

## Автопрогон

Создаёт временную uinput-клавиатуру, дёргает показ и **сразу** печатает зонд
`abcdefgh`, затем спрашивает у приложения, что оказалось в поле.

```sh
cargo build --features layer --examples
LAB_METRICS=/tmp/lab.csv LAB_WINDOW=layer ./target/debug/tauri-quick-lab &
./target/debug/examples/bench 20
```

Нужны права на uinput и input — те же, что для `bench-evdev` в slint-shell.
Ненулевой код возврата означает, что хотя бы одна попытка потеряла символы.

Ручки прогона: `LAB_TYPE_DELAY` (мс до первой клавиши, по умолчанию 0 —
самый жёсткий режим), `LAB_TYPE_INTERVAL` (мс между клавишами, 25),
`LAB_SETTLE` (мс до опроса результата, 700).

**Перед запуском переведите фокус в черновик, а не в терминал.** Зонд состоит
только из букв, без Enter, но потерянные символы попадут именно туда — и это
заодно ручная проверка утечки ввода в исходное окно.

## CSV

`trial,strategy,chars_sent,chars_landed,lost,ms_show,ms_frame,ms_os_focus,ms_dom_focus,ms_first_char`

Все `ms_*` — от `t0_trigger`, то есть от момента вызова в bench, а не от старта
процесса. Пропущенная метка остаётся **пустой ячейкой** и не подменяется нулём.
`ms_os_focus` привязывается к последней начатой попытке: событие фокуса от ОС
не несёт идентификатора.

Ключевые столбцы — `lost` и `ms_first_char`. Остальные нужны, чтобы понять,
**где** потерялось: до показа, до кадра, до фокуса ОС или до фокуса в DOM.

## Чего лаборатория не проверяет

- Фронтенд здесь голый HTML. Boot Vue в реальном приложении добавит своё время,
  и после переноса замер надо повторить на настоящем UI.
- Вставку текста обратно в исходное окно. Отдельная задача: в основном
  приложении по умолчанию `xdotool`, а он на Wayland не работает.
- GNOME: Mutter не реализует `zwlr_layer_shell_v1`, там `layer` молча
  деградирует в обычное окно. Проверяется отдельно и отдельно записывается.
- Windows и macOS: там другой механизм (`tauri-nspanel`, стили no-activate).
